
# 📘 Части 11: React Hook Form + Zod

## 11.1 Зачем нужна связка RHF + Zod

В Части 6 ты писал формы на «чистом» `useState` + вычисляемые ошибки. Это работает, но с ростом формы появляются проблемы:

- Много state → много ререндеров (каждое нажатие клавиши перерисовывает всю форму)
- Ручная логика `touched`, `errors`, `isSubmitting`
- Валидация размазана по компоненту
- Сложно переиспользовать правила валидации на бэкенде

**React Hook Form (RHF)** решает первые три проблемы: использует **неконтролируемые** инпуты (через `ref`), минимизирует ререндеры, даёт готовые `formState` (errors, isSubmitting, isValid, isDirty).

**Zod** решает четвёртую: схема валидации — это **декларативное описание** структуры данных. Её можно использовать и на клиенте, и на сервере (если сервер на Node).

**`@hookform/resolvers`** — мост между ними: `zodResolver(schema)` говорит RHF «валидируй через Zod».

## 11.3 Базовый паттерн (три шага)

### Шаг 1: Определить Zod-схему

```jsx
import { z } from 'zod';

const formSchema = z.object({
  name: z.string().min(2, 'Минимум 2 символа'),
  email: z.string().email('Некорректный email'),
  age: z.coerce.number().min(18, 'Только с 18 лет'),
});
```

> **`z.coerce.number()`** — важно для инпутов. HTML-инпут возвращает **строку**, даже если `type="number"`. `coerce` конвертирует её в число перед валидацией.

### Шаг 2: Вывести тип (если TypeScript) или JSDoc

```jsx
type FormData = z.infer<typeof formSchema>;
// В JS: /** @typedef {z.infer<typeof formSchema>} FormData */
```

### Шаг 3: Подключить к `useForm`

```jsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';

function MyForm() {
  const {
    register,           // подключает инпут к форме
    handleSubmit,       // оборачивает onSubmit
    formState: { errors, isSubmitting, isValid, isDirty },
  } = useForm({
    resolver: zodResolver(formSchema), // ← мост к Zod
    mode: 'onChange',                  // валидация на лету
    defaultValues: { name: '', email: '', age: '' },
  });

  const onSubmit = async (data) => {
    console.log('Валидные данные:', data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('name')} placeholder="Имя" />
      {errors.name && <p style={{ color: 'red' }}>{errors.name.message}</p>}

      <input {...register('email')} placeholder="Email" />
      {errors.email && <p style={{ color: 'red' }}>{errors.email.message}</p>}

      <button type="submit" disabled={isSubmitting}>
        Отправить
      </button>
    </form>
  );
}
```

**Ключевой момент:** `{...register('name')}` возвращает `{ name, onChange, onBlur, ref }`. RHF **не хранит значение в state** — он читает его из DOM через `ref`. Поэтому ререндеров почти нет.

---

## 11.4 `formState` — что внутри

| Свойство | Что даёт |
|----------|----------|
| `errors` | Объект ошибок по полям: `errors.email.message` |
| `isSubmitting` | `true` пока `onSubmit` не завершится |
| `isValid` | `true` если вся форма валидна (нужен `mode: 'onChange'`) |
| `isDirty` | `true` если пользователь что-то менял |
| `touchedFields` | Какие поля «трогали» |
| `dirtyFields` | Какие поля изменены |

## 11.5 Сложные кейсы Zod

### Кросс-полевая валидация (пароли)

```jsx
const passwordSchema = z
  .object({
    password: z.string().min(8, 'Минимум 8 символов'),
    confirmPassword: z.string(),
  })
  .refine((data) => data.password === data.confirmPassword, {
    message: 'Пароли не совпадают',
    path: ['confirmPassword'], // ошибка привяжется к этому полю
  });
```

`path` указывает, к какому полю привязать ошибку. Без него ошибка попадёт в `errors.root`.

### Массивы (динамические поля)

```jsx
const orderSchema = z.object({
  items: z
    .array(
      z.object({
        name: z.string().min(1, 'Название обязательно'),
        quantity: z.coerce.number().int().positive('Количество > 0'),
        price: z.coerce.number().positive('Цена > 0'),
      })
    )
    .min(1, 'Добавьте хотя бы один товар'),
});
```

Для рендера и управления массивом в RHF есть **`useFieldArray`**:

```jsx
import { useFieldArray } from 'react-hook-form';

const { fields, append, remove } = useFieldArray({ control, name: 'items' });

// fields.map((field, index) => (
//   <input {...register(`items.${index}.name`)} key={field.id} />
// ))
```

`field.id` — служебный уникальный ключ от RHF, **не путать с id из данных**.

### Enum (select)

```jsx
role: z.enum(['admin', 'editor', 'viewer']),
```

## 11.6 🎯 Практика Части 11: Форма создания пользователя

### `src/schemas/userSchema.js`

```jsx
import { z } from 'zod';

export const userSchema = z
  .object({
    name: z.string().min(2, 'Минимум 2 символа'),
    email: z.string().email('Некорректный email'),
    age: z.coerce.number().int().min(18, 'Только с 18 лет'),
    role: z.enum(['admin', 'editor', 'viewer']),
    password: z.string().min(8, 'Минимум 8 символов'),
    confirmPassword: z.string(),
    bio: z.string().max(500, 'Максимум 500 символов').optional(),
  })
  .refine((data) => data.password === data.confirmPassword, {
    message: 'Пароли не совпадают',
    path: ['confirmPassword'],
  });
```

### `src/components/UserForm.jsx`

```jsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { userSchema } from '../schemas/userSchema';

function UserForm({ onSubmit }) {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting, isValid, isDirty },
    reset,
  } = useForm({
    resolver: zodResolver(userSchema),
    mode: 'onChange', // валидация на лету
    defaultValues: {
      name: '',
      email: '',
      age: '',
      role: 'viewer',
      password: '',
      confirmPassword: '',
      bio: '',
    },
  });

  async function handleFormSubmit(data) {
    await onSubmit(data);
    reset(); // очищаем после успешной отправки
  }

  return (
    <form onSubmit={handleSubmit(handleFormSubmit)} noValidate>
      <div>
        <label>Имя</label>
        <input {...register('name')} />
        {errors.name && <p style={{ color: 'red' }}>{errors.name.message}</p>}
      </div>

      <div>
        <label>Email</label>
        <input type="email" {...register('email')} />
        {errors.email && <p style={{ color: 'red' }}>{errors.email.message}</p>}
      </div>

      <div>
        <label>Возраст</label>
        <input type="number" {...register('age')} />
        {errors.age && <p style={{ color: 'red' }}>{errors.age.message}</p>}
      </div>

      <div>
        <label>Роль</label>
        <select {...register('role')}>
          <option value="viewer">Viewer</option>
          <option value="editor">Editor</option>
          <option value="admin">Admin</option>
        </select>
      </div>

      <div>
        <label>Пароль</label>
        <input type="password" {...register('password')} />
        {errors.password && <p style={{ color: 'red' }}>{errors.password.message}</p>}
      </div>

      <div>
        <label>Повтор пароля</label>
        <input type="password" {...register('confirmPassword')} />
        {errors.confirmPassword && (
          <p style={{ color: 'red' }}>{errors.confirmPassword.message}</p>
        )}
      </div>

      <div>
        <label>О себе</label>
        <textarea {...register('bio')} rows={3} />
        {errors.bio && <p style={{ color: 'red' }}>{errors.bio.message}</p>}
      </div>

      <button type="submit" disabled={!isValid || isSubmitting || !isDirty}>
        {isSubmitting ? 'Отправка...' : 'Создать'}
      </button>
    </form>
  );
}

export default UserForm;
```

**Что тренировали:**
- Zod-схема с кросс-полевой валидацией (`refine`)
- `z.coerce.number()` для числового инпута
- `z.enum()` для select
- `register` для всех полей
- `formState`: `errors`, `isSubmitting`, `isValid`, `isDirty`
- `mode: 'onChange'` — валидация при вводе
- `reset()` после сабмита

# 📘 Часть 12: TanStack Query (React Query)

## 12.1 Проблема «серверного состояния»

В Части 5 ты загружал данные через `useEffect` + `fetch` и вручную управлял `loading`/`error`/`data`. Это работает, но с ростом приложения появляются проблемы:

- **Кэш:** каждый переход на страницу — новый запрос, хотя данные не изменились
- **Race conditions:** быстрые переключения → старые ответы перезаписывают новые
- **Инвалидация:** после создания поста нужно вручную перезапросить список
- **Фоновая синхронизация:** данные устаревают, а приложение об этом не знает

**TanStack Query** (бывший React Query) — библиотека для **серверного состояния**. Она берёт на себя кэш, повторные запросы, инвалидацию, фоновое обновление, retry, пагинацию.

> **Ключевая идея:** ты больше не пишешь `useEffect` для загрузки данных. Ты описываешь **запрос** (`useQuery`) и **мутацию** (`useMutation`), а библиотека делает всё остальное.

---

## 12.2 Установка и настройка

```bash
npm install @tanstack/react-query
```

### `src/main.jsx`

```jsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

// QueryClient — «мозг» библиотеки: держит кэш и настройки по умолчанию
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,      // данные «свежие» 30 сек — повторный запрос не нужен
      retry: 2,               // 2 повторные попытки при ошибке
      refetchOnWindowFocus: false, // не перезапрашивать при возврате на вкладку
    },
  },
});

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <QueryClientProvider client={queryClient}>
      <BrowserRouter>
        <App />
      </BrowserRouter>
    </QueryClientProvider>
  </React.StrictMode>
);
```

**`QueryClientProvider`** должен быть **выше** всех компонентов, использующих хуки библиотеки.

## 12.3 `useQuery` — загрузка данных

### Синтаксис

```jsx
import { useQuery } from '@tanstack/react-query';

const { data, isLoading, isError, error, refetch } = useQuery({
  queryKey: ['users'],          // уникальный ключ кэша
  queryFn: () => fetch('/api/users').then(r => r.json()),
});
```

### `queryKey` — это адрес в кэше

Ключ — **массив**. Он определяет, какие данные кэшируются и когда их инвалидировать.

```jsx
// Список
useQuery({ queryKey: ['users'], queryFn: getUsers });

// Один пользователь
useQuery({ queryKey: ['users', userId], queryFn: () => getUser(userId) });

// С фильтром
useQuery({ queryKey: ['users', { role: 'admin' }], queryFn: ... });
```

**Правило:** если в `queryFn` используется переменная — она **должна** быть в `queryKey`. Иначе при её изменении запрос не перезапустится.

### Три состояния

| Состояние | Что значит |
|-----------|------------|
| `isPending` / `isLoading` | Запрос идёт, данных ещё нет |
| `isError` | Запрос упал (`error` содержит объект ошибки) |
| `isSuccess` | Данные есть (`data`) |

```jsx
if (isLoading) return <p>Загрузка...</p>;
if (isError) return <p>Ошибка: {error.message}</p>;
return <ul>{data.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
```

**Важно:** `useQuery` не бросает ошибку в рендер. Ты **обязан** обработать `isError` сам, иначе увидишь пустой экран.

## 12.4 `useMutation` — изменение данных

Мутации — это POST/PUT/DELETE. Они **не запускаются автоматически**, а вызываются через `mutate()`.

```jsx
import { useMutation, useQueryClient } from '@tanstack/react-query';

function AddUserForm() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (newUser) =>
      fetch('/api/users', {
        method: 'POST',
        body: JSON.stringify(newUser),
      }).then(r => r.json()),

    onSuccess: () => {
      // Инвалидируем кэш списка → useQuery перезапросит данные
      queryClient.invalidateQueries({ queryKey: ['users'] });
    },
  });

  return (
    <button
      onClick={() => mutation.mutate({ name: 'Иван' })}
      disabled={mutation.isPending}
    >
      {mutation.isPending ? 'Создание...' : 'Добавить'}
    </button>
  );
}
```

**`invalidateQueries`** — ключевой приём. После мутации ты говоришь: «данные с этим ключом устарели, перезапроси их». `useQuery` автоматически сделает новый запрос.

### Оптимистичное обновление (продвинуто)

Иногда хочется, чтобы UI обновился **сразу**, не дожидаясь сервера. Это `onMutate` + `onError` (rollback) + `onSettled` (инвалидация):

```jsx
useMutation({
  mutationFn: addTodo,
  onMutate: async (newTodo) => {
    await queryClient.cancelQueries({ queryKey: ['todos'] }); // отменяем текущие
    const previous = queryClient.getQueryData(['todos']);       // снимок
    queryClient.setQueryData(['todos'], (old = []) => [newTodo, ...old]); // оптимистично
    return { previous };                                         // контекст для rollback
  },
  onError: (err, newTodo, context) => {
    queryClient.setQueryData(['todos'], context.previous);       // откат
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['todos'] });      // синхронизация
  },
});
```

## 12.5 🎯 Практика Части 12: Список постов с созданием

Используем `jsonplaceholder.typicode.com` — публичный API с поддержкой POST (хотя реально не сохраняет).

### `src/api/posts.js`

```jsx
const BASE = 'https://jsonplaceholder.typicode.com';

export async function getPosts() {
  const res = await fetch(`${BASE}/posts?_limit=10`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

export async function createPost(data) {
  const res = await fetch(`${BASE}/posts`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data),
  });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}
```

### `src/components/PostsList.jsx`

```jsx
import { useQuery } from '@tanstack/react-query';
import { getPosts } from '../api/posts';

function PostsList() {
  const { data, isLoading, isError, error, refetch, isFetching } = useQuery({
    queryKey: ['posts'],
    queryFn: getPosts,
  });

  if (isLoading) return <p>Загрузка постов...</p>;
  if (isError) {
    return (
      <div>
        <p style={{ color: 'red' }}>Ошибка: {error.message}</p>
        <button onClick={() => refetch()}>Повторить</button>
      </div>
    );
  }

  return (
    <div>
      {/* isFetching — true при фоновом обновлении, даже если данные уже есть */}
      {isFetching && <p style={{ color: '#888' }}>Обновление...</p>}

      <ul>
        {data.map((post) => (
          <li key={post.id}>
            <strong>{post.title}</strong>
            <p style={{ fontSize: 13, color: '#666' }}>{post.body}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default PostsList;
```

### `src/components/AddPostForm.jsx`

```jsx
import { useState } from 'react';
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { createPost } from '../api/posts';

function AddPostForm() {
  const [title, setTitle] = useState('');
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: createPost,
    onSuccess: () => {
      // Инвалидируем кэш постов → список перезапросится
      queryClient.invalidateQueries({ queryKey: ['posts'] });
      setTitle(''); // очищаем форму
    },
  });

  function handleSubmit(e) {
    e.preventDefault();
    if (!title.trim()) return;

    // mutate — запуск мутации. Можно передать колбэки вторым аргументом.
    mutation.mutate(
      { title, body: 'Новый пост', userId: 1 },
      {
        onError: (err) => alert(`Ошибка: ${err.message}`),
      }
    );
  }

  return (
    <form onSubmit={handleSubmit} style={{ marginBottom: 20 }}>
      <input
        value={title}
        onChange={(e) => setTitle(e.target.value)}
        placeholder="Заголовок поста"
        style={{ padding: 8, marginRight: 8 }}
      />
      <button type="submit" disabled={mutation.isPending}>
        {mutation.isPending ? 'Создание...' : 'Создать'}
      </button>

      {/* mutation.isError доступен, если не обрабатываешь onError в mutate */}
      {mutation.isError && (
        <p style={{ color: 'red' }}>Ошибка: {mutation.error.message}</p>
      )}
    </form>
  );
}

export default AddPostForm;
```
