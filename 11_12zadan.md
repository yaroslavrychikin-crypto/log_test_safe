# Комплексная задача на отработку Дней 11–12

**Тема:** CRUD-приложение «Каталог постов» с формой на React Hook Form + Zod и загрузкой/мутациями через TanStack Query.

---

## 📋 Условие задачи

Собери приложение **«Блог»** с тремя экранами:

1. **Список постов** (`/posts`) — загрузка через `useQuery`, кнопка «Создать пост» → форма.
2. **Форма поста** (`/posts/new` и `/posts/:id/edit`) — одна и та же форма для создания и редактирования, RHF + Zod.
3. **Детали поста** (`/posts/:id`) — загрузка одного поста через `useQuery` с ключом, зависящим от `id`.

### API

Используем `https://jsonplaceholder.typicode.com` — публичный API:
- `GET /posts?_limit=10` — список
- `GET /posts/:id` — один пост
- `POST /posts` — создание (реально не сохраняет, но отвечает 201)
- `PUT /posts/:id` — обновление
- `DELETE /posts/:id` — удаление

> **Важно:** jsonplaceholder **не сохраняет** изменения. После `invalidateQueries` список вернётся к исходному состоянию. Это нормально — мы тренируем **технику**, а не бэкенд. Для наглядности используй оптимистичные обновления — тогда UI будет показывать изменения до инвалидации.

## Функциональные требования

### 1. Список постов

- Загрузка через `useQuery({ queryKey: ['posts'], queryFn: getPosts })`
- Три состояния: `isLoading` → «Загрузка...», `isError` → ошибка + кнопка «Повторить» (`refetch`), успех → список
- Каждый пост: заголовок (ссылка на `/posts/:id`), краткое описание, кнопки «Редактировать» и «Удалить»
- Кнопка «Создать пост» → `/posts/new`
- При удалении — `useMutation` + оптимистичное обновление: пост исчезает из списка **сразу**, при ошибке — возвращается

>**Подсказка: как устроено оптимистичное удаление**

Три колбэка у `useMutation`:
- **`onMutate`** — сохраняешь «снимок» кэша (`getQueryData`), затем **сразу** обновляешь его (`setQueryData`) — как будто успех. Верни `{ previous }` — это станет `context` в следующих колбэках.
- **`onError`** — если запрос упал, восстанавливаешь кэш из `context.previous`.
- **`onSettled`** — в любом случае (успех/ошибка) инвалидируешь кэш, чтобы синхронизироваться с сервером.

Перед `setQueryData` полезно вызвать `await queryClient.cancelQueries(...)`, чтобы летящие запросы не перезаписали твой оптимистичный кэш.

>**Подсказка: как получить доступ к queryClient**

`const queryClient = useQueryClient()` — хук из `@tanstack/react-query`. Даёт методы `getQueryData`, `setQueryData`, `invalidateQueries`, `removeQueries`, `cancelQueries`.

### 2. Форма поста (общая для создания и редактирования)

**Zod-схема:**

| Поле | Правила |
|------|---------|
| `title` | строка, 3–100 символов |
| `body` | строка, 10–1000 символов |
| `userId` | `z.coerce.number().int().positive()` |
| `tags` | массив строк, 1–5 элементов, каждый тег 2–20 символов |
| `status` | `z.enum(['draft', 'published'])` |
| `publishDate` | строка `YYYY-MM-DD`, не в прошлом — через `refine` |

**RHF:**
- `mode: 'onChange'` — валидация на лету
- Кнопка «Сохранить» disabled, если `!isValid || isSubmitting || !isDirty` (для режима редактирования)
- `useFieldArray` для тегов: кнопки «Добавить тег» / «Удалить тег»
- При редактировании: `defaultValues` подгружаются из `useQuery` по `id`
- После успешного сабмита — `navigate('/posts')` и `invalidateQueries({ queryKey: ['posts'] })`

**Обработка ошибок сервера:**
- Если сервер вернул `{ field: 'title', message: '...' }` — вызвать `setError('title', { message })` и показать ошибку под полем

>**Подсказка: схема Zod для массива и refine**

Опиши массив тегов как `z.array(...)` с `.min(1).max(5)`, а каждый элемент — строка с ограничениями длины. Для даты используй `refine`: сравнивай не с текущим моментом, а с началом сегодняшнего дня (`new Date().setHours(0,0,0,0)`), чтобы «сегодня» считалось валидным. `z.enum(['draft', 'published'])` сам выдаст ошибку, если значение не совпадает.

>**Подсказка: как подключить useFieldArray**

`useFieldArray({ control, name: 'tags' })` возвращает `{ fields, append, remove }`.
- `fields` — служебные объекты с `field.id` (используй как `key` в `map`, **не** путай с данными)
- `append('')` — добавляет пустую строку (Zod потом скажет «минимум 2 символа»)
- `register(\`tags.${index}\`)` — регистрирует инпут для конкретного индекса

Ошибки по тегам приходят по-разному:
- `errors.tags?.root` — ошибки уровня массива (min/max)
- `errors.tags?.[i]?.message` — ошибка конкретного тега

>**Подсказка: как подгрузить defaultValues при редактировании**

`defaultValues` в `useForm` задаются один раз при монтировании. Если данные асинхронные — **самый простой путь**: в `EditPostPage` рендери `PostForm` **только когда данные загружены** (сначала `if (isLoading) return <p>Загрузка...</p>`). Тогда `useForm({ defaultValues: initialData ?? defaultPostValues })` сразу получает правильные значения. Альтернатива — `reset(data)` в `useEffect` при изменении `data`, но это сложнее и легче ошибиться.

>**Подсказка: как передать ошибку сервера в поле**

`useForm` возвращает `setError`. Внутри `PostForm` оберни вызов `onSubmit` в `try/catch`: если в ошибке есть `err.field` — вызывай `setError(err.field, { message: err.message, type: 'server' })`, иначе — `setError('root.serverError', { message: err.message })`. Чтобы `PostForm` мог поймать ошибку, родитель должен использовать **`mutateAsync`** (возвращает Promise и пробрасывает исключение), а **не** `mutate` (глотает ошибку).

### 3. Детали поста

- `useQuery({ queryKey: ['posts', id], queryFn: () => getPost(id) })`
- Если `isError` → «Пост не найден» + ссылка назад
- Кнопки «Редактировать» → `/posts/:id/edit`, «Удалить» → мутация + `navigate('/posts')`

>**Подсказка: почему id в queryKey обязателен**

Если ключ `['posts']` для списка и `['post']` для деталей — кэш общий, и при переходе с поста 1 на пост 2 `useQuery` вернёт **старые данные поста 1**. Правило: **все переменные из `queryFn` должны быть в `queryKey`**. Для деталей — `['posts', id]`. Для списка — `['posts']`. Бонус: `invalidateQueries({ queryKey: ['posts'] })` инвалидирует **всё, что начинается с `['posts']`** — и список, и все детали.

>**Подсказка: удаление из деталей**

После успешного удаления стоит сделать `removeQueries({ queryKey: ['posts', id] })` — чтобы данные удалённого поста не остались в кэше. Затем `invalidateQueries({ queryKey: ['posts'] })` для списка и `navigate('/posts')`.

### 4. Общие требования

- `QueryClientProvider` в `main.jsx`, `staleTime: 30_000`, `retry: 1`
- Все запросы — в `src/api/posts.js`
- Все схемы — в `src/schemas/postSchema.js`
- `queryKey` включает все переменные из `queryFn`
- Обработка `isPending` у мутаций (disabled на кнопках)

## Чек-лист самопроверки

- [ ] Все поля схемы покрыты, включая `z.coerce.number()` для числовых инпутов

- [ ] Для статуса — `z.enum([...])`
- [ ] Для даты — `refine`, а не `z.date()` (инпут отдаёт строку)

**RHF:**
- [ ] `mode: 'onChange'` — иначе `isValid` не работает на лету
- [ ] `defaultValues` для create (`defaultPostValues`) и edit (`initialData`) — два режима
- [ ] `useFieldArray` с `key={field.id}`, `register(\`tags.${index}\`)`
- [ ] `formState.errors` отображены под каждым полем
- [ ] Ошибка массива (`errors.tags?.root`) и ошибки элементов (`errors.tags?.[i]`) обрабатываются отдельно
- [ ] `setError` для ошибок сервера
- [ ] Кнопка disabled при `!isValid || isSubmitting || (!isDirty && isEdit)`

**TanStack Query:**
- [ ] `QueryClientProvider` в `main.jsx`, `staleTime: 30_000`, `retry: 1`
- [ ] `queryKey` включает все переменные из `queryFn`
- [ ] `useQuery` — три состояния: `isLoading` / `isError` / `data`
- [ ] `useMutation` — `isPending` на кнопках
- [ ] `invalidateQueries` после успешной мутации
- [ ] `mutateAsync` в `PostForm` (а не `mutate`) — чтобы поймать ошибку и вызвать `setError`
- [ ] Оптимистичное удаление: `onMutate` + `onError` + `onSettled`

**Роутинг:**
- [ ] `/posts/new` объявлен **до** `/posts/:id` (иначе `new` уйдёт в `:id`)
- [ ] При редактировании `PostForm` рендерится только после загрузки данных (для `defaultValues`)

## 🚀 Дополнительные задания (если закончил раньше)

1. **Поиск по заголовку**: `queryKey: ['posts', { search }]` (или фильтрация на клиенте через `useMemo`).
2. **Пагинация**: `queryKey: ['posts', page]`, кнопки Назад/Вперёд.
3. **Оптимистичное создание**: `onMutate` вставляет пост с временным `id: 'temp-' + Date.now()`, `onSettled` инвалидирует.
4. **Кэширование деталей перед переходом**: `queryClient.setQueryData(['posts', id], post)` при клике на пост из списка — детали откроются мгновенно.
5. **Ошибка «Пост не найден»** через `retry: false` для деталей: `useQuery({ ..., retry: false })`.
6. **Хук-обёртки** `usePosts()` и `usePost(id)` — вынеси `useQuery` из компонентов, чтобы переиспользовать.
