# 📘 Часть 14: Финальный проект

## 14.0 Что должно быть в финальном проекте

Финальный проект — это **не про новую технологию**, а про **интеграцию**. Ты уже знаешь все инструменты по отдельности. Задача — собрать их в одно приложение так, чтобы каждое решение было обоснованным.

### Обязательный стек

| Технология | Где используется | Зачем в проекте |
|------------|------------------|-----------------|
| React + Vite | База | Быстрый dev-сервер, простая сборка |
| TypeScript | Весь проект | Ловит ошибки до рантайма, документирует контракты |
| React Router v6 | 3+ страницы, динамический маршрут, 404 | Навигация без перезагрузки |
| `useState` / `useReducer` | Локальное состояние | Простые значения — `useState`, сложная логика — `useReducer` |
| Context API | Глобальное состояние (тема или авторизация) | Убирает prop drilling |
| `useEffect` | Работа с `localStorage` / API | Синхронизация с внешним миром |
| React Hook Form + Zod | Минимум одна форма | Валидация, минимум ререндеров |
| TanStack Query | Загрузка данных с API | Кэш, loading/error, инвалидация |
| `useMemo` / `useCallback` / `React.memo` | Минимум в одном месте | Стабилизация ссылок, оптимизация |
| `useLocalStorage` (кастомный хук) | Сохранение настроек | Переиспользование логики |

### Функциональные требования

**Страницы:**

1. **`/` — Dashboard**
   - Статистика: всего задач, выполнено, активно, по проектам
   - Кнопка «Перейти к задачам»

2. **`/tasks` — Список задач**
   - Фильтры: все / активные / выполненные (в query-параметре `?filter=active`)
   - Поиск по названию (debounce 300 мс)
   - Форма добавления (React Hook Form + Zod)
   - Список задач с чекбоксами, кнопками «Редактировать» / «Удалить»
   - Сохранение в `localStorage` через `useLocalStorage`

3. **`/tasks/:id` — Детали задачи**
   - Полная информация, кнопка «Назад» (`navigate(-1)`)
   - Кнопки «Редактировать», «Удалить»
   - Если задачи нет — «Не найдено» + ссылка

4. **`/settings` — Настройки**
   - Переключатель темы (light/dark) через Context + `localStorage`
   - Сброс всех данных (с `confirm`)

5. **`*` — 404** (вне Layout, без шапки)

**Глобальное состояние:**

- **Тема** — Context API, значение в `localStorage`
- **Задачи** — тоже Context (или `useLocalStorage` на верхнем уровне), доступны всем страницам

## 14.2 TS-версия: полный разбор

### `src/api/tasks.ts`

```tsx
// Базовый URL — вынесен, чтобы легко менять окружение
const BASE = 'https://jsonplaceholder.typicode.com';

// Тип «сырого» ответа API — ровно то, что приходит с jsonplaceholder.
// Отдельный тип нужен, потому что API может отдавать не всё, что мы хотим.
export interface ApiTask {
  userId: number;
  id: number;
  title: string;
  body: string;
  completed?: boolean; // в jsonplaceholder есть не всегда
}

// Универсальная обёртка: проверка res.ok + парсинг JSON + типизированный ответ.
// Generic <T> — чтобы каждый вызов указывал, что ожидает получить.
async function request<T>(path: string, options: RequestInit = {}): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    headers: { 'Content-Type': 'application/json', ...options.headers },
    ...options,
  });

  if (!res.ok) {
    // Пытаемся достать сообщение, если сервер его прислал
    let message = `HTTP ${res.status}`;
    try {
      const body = await res.json();
      if (body?.message) message = body.message;
    } catch {
      /* ignore */
    }
    throw new Error(message);
  }

  // 204 No Content — тела нет, возвращаем null как T
  if (res.status === 204) return null as T;
  return res.json() as Promise<T>;
}

// Типизированные обёртки над request
export function getTasks(): Promise<ApiTask[]> {
  return request<ApiTask[]>('/todos?_limit=20');
}

export function getTask(id: string): Promise<ApiTask> {
  return request<ApiTask>(`/todos/${id}`);
}

export function createTask(data: Omit<ApiTask, 'id'>): Promise<ApiTask> {
  return request<ApiTask>('/todos', {
    method: 'POST',
    body: JSON.stringify(data),
  });
}

export function updateTask({ id, ...data }: ApiTask): Promise<ApiTask> {
  return request<ApiTask>(`/todos/${id}`, {
    method: 'PUT',
    body: JSON.stringify(data),
  });
}

export function deleteTask(id: number): Promise<void> {
  return request<void>(`/todos/${id}`, { method: 'DELETE' });
}
```

**Ключевые решения:**
- `request<T>` — generic-функция: тип ответа задаётся в месте вызова
- `Omit<ApiTask, 'id'>` в `createTask` — «всё, кроме `id`» (его генерирует сервер)
- `Promise<void>` у `deleteTask` — честно говорим, что тело не нужно

### `src/schemas/taskSchema.ts`

```tsx
import { z } from 'zod';

// Схема формы создания задачи.
// z.infer извлечёт из неё TypeScript-тип.
export const taskSchema = z.object({
  title: z
    .string()
    .min(3, 'Минимум 3 символа')
    .max(100, 'Максимум 100 символов'),

  body: z
    .string()
    .min(10, 'Минимум 10 символов')
    .max(500, 'Максимум 500 символов'),

  userId: z.coerce
    .number({ invalid_type_error: 'Введите число' })
    .int('Только целое')
    .positive('Должно быть положительным'),

  priority: z.enum(['low', 'medium', 'high']),
});

// Тип формы: { title: string; body: string; userId: number; priority: 'low' | 'medium' | 'high' }
export type TaskFormValues = z.infer<typeof taskSchema>;

// Значения по умолчанию — отдельно, чтобы переиспользовать
export const defaultTaskValues: TaskFormValues = {
  title: '',
  body: '',
  userId: 1,
  priority: 'medium',
};
```

### `src/hooks/useLocalStorage.ts`

```tsx
import { useEffect, useState } from 'react';

// Generic-хук: T — тип хранимого значения.
// Вызывающий указывает, что ожидает: useLocalStorage<number[]>('ids', [])
export function useLocalStorage<T>(key: string, initialValue: T) {
  const [value, setValue] = useState<T>(() => {
    try {
      const saved = localStorage.getItem(key);
      if (saved !== null) return JSON.parse(saved) as T;
      return initialValue;
    } catch {
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch (err) {
      console.warn(`useLocalStorage: не удалось сохранить "${key}"`, err);
    }
  }, [key, value]);

  return [value, setValue] as const; // as const → кортеж [T, Dispatch<SetStateAction<T>>]
}
```

**Ключевое:** `as const` превращает возвращаемый массив в **кортеж** — иначе TS выведет `(T | Dispatch)[]` и деструктуризация сломается.

### `src/context/FavoritesContext.tsx`

```tsx
import { createContext, useContext, type ReactNode } from 'react';
import { useLocalStorage } from '../hooks/useLocalStorage';

// Контракт контекста: что доступно потребителям
interface FavoritesContextValue {
  favorites: number[];
  toggleFavorite: (id: number) => void;
  isFavorite: (id: number) => boolean;
}

// null по умолчанию — чтобы отловить «нет Provider»
const FavoritesContext = createContext<FavoritesContextValue | null>(null);

interface FavoritesProviderProps {
  children: ReactNode;
}

export function FavoritesProvider({ children }: FavoritesProviderProps) {
  // Избранное хранится в localStorage автоматически
  const [favorites, setFavorites] = useLocalStorage<number[]>('favorites', []);

  function toggleFavorite(id: number) {
    setFavorites((prev) =>
      prev.includes(id) ? prev.filter((x) => x !== id) : [...prev, id]
    );
  }

  function isFavorite(id: number) {
    return favorites.includes(id);
  }

  return (
    <FavoritesContext.Provider value={{ favorites, toggleFavorite, isFavorite }}>
      {children}
    </FavoritesContext.Provider>
  );
}

// Кастомный хук с проверкой на null — единственное место, где обрабатываем «нет Provider»
export function useFavorites() {
  const ctx = useContext(FavoritesContext);
  if (!ctx) throw new Error('useFavorites must be used within FavoritesProvider');
  return ctx;
}
```

import { useForm } from 'react-hook-form';

interface TaskFormProps {
  onSubmit: (data: TaskFormValues) => Promise<void>;

    register,
    handleSubmit,
    reset,

### `src/pages/TasksPage.tsx`

```tsx
import { useMemo } from 'react';
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { getTasks, createTask } from '../api/tasks';
import TaskCard from '../components/TaskCard';
import TaskForm from '../components/TaskForm';
import type { TaskFormValues } from '../schemas/taskSchema';

export default function TasksPage() {
  const queryClient = useQueryClient();

  const { data, isLoading, isError, error, refetch } = useQuery({
    queryKey: ['tasks'],
    queryFn: getTasks,
  });

  const mutation = useMutation({
    mutationFn: (values: TaskFormValues) =>
      createTask({
        title: values.title,
        body: values.body,
        userId: values.userId,
        completed: false,
      }),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['tasks'] });
    },
  });

  // useMemo: сортировка по id — пересчитывается только при изменении data
  const sorted = useMemo(() => {
    if (!data) return [];
    return [...data].sort((a, b) => a.id - b.id);
  }, [data]);

  if (isLoading) return <p>Загрузка...</p>;
  if (isError) {
    return (
      <div>
        <p style={{ color: 'red' }}>Ошибка: {error.message}</p>
        <button onClick={() => refetch()}>Повторить</button>
      </div>
    );
  }

  return (
    <div>
      <h1>Задачи</h1>
      <TaskForm onSubmit={(values) => mutation.mutateAsync(values)} />
      <ul style={{ listStyle: 'none', padding: 0, marginTop: 20 }}>
        {sorted.map((task) => (
          <TaskCard key={task.id} task={task} />
        ))}
      </ul>
    </div>
  );
}
```

## 14.3 JS-версия: те же файлы, те же идеи

Ниже — только те файлы, где есть **содержательные** отличия от TS. Всё остальное (логика, CSS, роуты) — идентично.

### `src/api/tasks.js`

```jsx
const BASE = 'https://jsonplaceholder.typicode.com';

// JSDoc-комментарий — «бедный человек TypeScript»:
// редактор его частично понимает, но проверки нет
/**
 * @param {string} path
 * @param {RequestInit} [options]
 * @returns {Promise<any>}
 */
async function request(path, options = {}) {
  const res = await fetch(`${BASE}${path}`, {
    headers: { 'Content-Type': 'application/json', ...options.headers },
    ...options,
  });

  if (!res.ok) {
    let message = `HTTP ${res.status}`;
    try {
      const body = await res.json();
      if (body?.message) message = body.message;
    } catch {}
    throw new Error(message);
  }

  if (res.status === 204) return null;
  return res.json();
}

// Здесь тип ответа НЕ проверяется — можно случайно использовать
// поле, которого нет (task.completedAt) — и узнать только в рантайме
export function getTasks() {
  return request('/todos?_limit=20');
}

export function getTask(id) {
  return request(`/todos/${id}`);
}

export function createTask(data) {
  return request('/todos', { method: 'POST', body: JSON.stringify(data) });
}

export function updateTask({ id, ...data }) {
  return request(`/todos/${id}`, { method: 'PUT', body: JSON.stringify(data) });
}

export function deleteTask(id) {
  return request(`/todos/${id}`, { method: 'DELETE' });
}
```

**Что пропало:**
- Generic `request<T>` — тип ответа не проверяется
- `ApiTask` — нет структуры задачи. Если опечатаешься в `task.tittle` — только в рантайме
- `Omit<ApiTask, 'id'>` — нет гарантии, что `id` не передаётся

**Что осталось тем же:** сам `fetch`, проверка `res.ok`, обработка 204 — логика **идентична**.

### `src/schemas/taskSchema.js`

```jsx
import { z } from 'zod';

// Схема Zod идентична — она не зависит от TS
export const taskSchema = z.object({
  title: z.string().min(3, 'Минимум 3 символа').max(100, 'Максимум 100 символов'),
  body: z.string().min(10, 'Минимум 10 символов').max(500, 'Максимум 500 символов'),
  userId: z.coerce.number().int().positive(),
  priority: z.enum(['low', 'medium', 'high']),
});

// В JS нет z.infer — тип формы «живёт в голове» разработчика
// и в структуре defaultTaskValues. Если добавишь поле в схему,
// но забудешь в defaultTaskValues — RHF может молча его не отправлять.

export const defaultTaskValues = {
  title: '',
  body: '',
  userId: 1,
  priority: 'medium',
};
```

**Что пропало:** `z.infer<typeof taskSchema>` — единый источник типа. В JS структура «в голове» + в `defaultTaskValues`, а при изменении схемы ручной синхронизации нет.

### `src/hooks/useLocalStorage.js`

```jsx
import { useEffect, useState } from 'react';

// JSDoc помогает редактору, но проверки нет
/**
 * @template T
 * @param {string} key
 * @param {T} initialValue
 * @returns {[T, (value: T | ((prev: T) => T)) => void]}
 */
export function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const saved = localStorage.getItem(key);
      if (saved !== null) return JSON.parse(saved);
      return initialValue;
    } catch {
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch (err) {
      console.warn(`useLocalStorage: не удалось сохранить "${key}"`, err);
    }
  }, [key, value]);

  return [value, setValue];
}
```

**Что пропало:** `T` в сигнатуре, `as const` для кортежа. Всё остальное — то же самое.

**Обрати внимание:** если использовать этот хук с объектом, в JS легко забыть, что хранится **сериализованное** значение: `JSON.parse` вернёт «плоский» объект без методов.

### `src/context/FavoritesContext.jsx`

```jsx
import { createContext, useContext } from 'react';
import { useLocalStorage } from '../hooks/useLocalStorage';

// В JS нет интерфейса — контракт контекста «в голове».
// Если потребитель ждёт { isFavorite }, а провайдер забыл его положить — упадёт в рантайме.
const FavoritesContext = createContext(null);

export function FavoritesProvider({ children }) {
  const [favorites, setFavorites] = useLocalStorage('favorites', []);

  function toggleFavorite(id) {
    setFavorites((prev) => (prev.includes(id) ? prev.filter((x) => x !== id) : [...prev, id]));
  }

  function isFavorite(id) {
    return favorites.includes(id);
  }

  return (
    <FavoritesContext.Provider value={{ favorites, toggleFavorite, isFavorite }}>
      {children}
    </FavoritesContext.Provider>
  );
}

export function useFavorites() {
  const ctx = useContext(FavoritesContext);
  if (!ctx) throw new Error('useFavorites must be used within FavoritesProvider');
  return ctx;
}
```

**Что пропало:** `FavoritesContextValue` — нет контракта. Если добавишь `clearFavorites` в провайдер, но забудешь в значении — потребитель молча получит `undefined`.

### `src/pages/TasksPage.jsx`

```jsx
import { useMemo } from 'react';
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { getTasks, createTask } from '../api/tasks';
import TaskCard from '../components/TaskCard';
import TaskForm from '../components/TaskForm';

export default function TasksPage() {
  const queryClient = useQueryClient();

  const { data, isLoading, isError, error, refetch } = useQuery({
    queryKey: ['tasks'],
    queryFn: getTasks,
  });

  const mutation = useMutation({
    mutationFn: (values) => createTask({ title: values.title, body: values.body, userId: values.userId, completed: false }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['tasks'] }),
  });

  const sorted = useMemo(() => {
    if (!data) return [];
    return [...data].sort((a, b) => a.id - b.id);
  }, [data]);

  if (isLoading) return <p>Загрузка...</p>;
  if (isError) {
    return (
      <div>
        <p style={{ color: 'red' }}>Ошибка: {error.message}</p>
        <button onClick={() => refetch()}>Повторить</button>
      </div>
    );
  }

  return (
    <div>
      <h1>Задачи</h1>
      <TaskForm onSubmit={(values) => mutation.mutateAsync(values)} />
      <ul style={{ listStyle: 'none', padding: 0, marginTop: 20 }}>
        {sorted.map((task) => <TaskCard key={task.id} task={task} />)}
      </ul>
    </div>
  );
}
```

**Что пропало:** `values: TaskFormValues` — `values` будет `any`. Опечатка в `values.tittle` — только в рантайме.

## 14.4 Сводная таблица: что меняется JS → TS

| Файл | JS | TS | Что даёт TS |
|------|----|----|-------------|
| `api/tasks` | `request(path, options)` | `request<T>(path, options)` | Тип ответа известен в месте вызова |
| `api/tasks` | нет `ApiTask` | `interface ApiTask` | Автодополнение полей задачи |
| `api/tasks` | `createTask(data)` | `createTask(data: Omit<ApiTask, 'id'>)` | Нельзя случайно передать `id` |
| `schemas/taskSchema` | нет `z.infer` | `export type TaskFormValues = z.infer<...>` | Один источник правды: схема → тип |
| `hooks/useLocalStorage` | JSDoc | `useLocalStorage<T>` + `as const` | Тип значения и кортеж возврата |
| `context/FavoritesContext` | `createContext(null)` | `createContext<FavoritesContextValue \| null>(null)` | Контракт контекста, автодополнение |
| `components/TaskCard` | `TaskCard({ task })` | `TaskCard({ task }: TaskCardProps)` | Ошибка, если `task` не того типа |
| `components/TaskForm` | `useForm({...})` | `useForm<TaskFormValues>({...})` | `register('tittle')` — ошибка |
| `pages/TasksPage` | `(values) => ...` | `(values: TaskFormValues) => ...` | Поля `values` проверяются |
| `pages/TaskDetailPage` | `useParams()` | `useParams<{ id: string }>()` | `id` — `string \| undefined` |
| `main` | `getElementById('root')` | `getElementById('root')!` | Явное «я уверен» |

**Что НЕ меняется:**
- Вся логика компонентов
- `useQuery`, `useMutation`, `invalidateQueries`
- `useForm`, `register`, `handleSubmit`, `formState`
- Zod-схема (она **одинаковая** в JS и TS)
- CSS, стили, структура папок
- Роутинг, `NavLink`, `Outlet`
- `memo`, `useMemo`, `useCallback`

**Правило:** TypeScript — это **надстройка**, а не другой фреймворк. 90% кода одинаково, 10% — типы, которые ловят ошибки заранее.
