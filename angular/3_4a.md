### Часть 3: Взаимодействие и Директивы

**Цель:** Научиться реагировать на действия пользователя и выводить динамические списки.

#### 1. Теория: Привязка данных и новый синтаксис шаблонов

В Angular есть три основных способа связи класса компонента и шаблона:

1.  **Интерполяция** `{{ }}`: Вывод значения в текст (вы уже использовали).
2.  **Привязка свойств** `[property]="value"`: Передача данных в HTML-атрибуты или входные параметры компонентов.
3.  **Привязка событий** `(event)="method()"`: Реакция на клики, ввод и т.д.

**Важное обновление (Angular 17+):** Вместо старых директив `*ngIf` и `*ngFor` теперь используется **блоковый синтаксис** прямо в шаблоне. Он работает «из коробки», не требует импорта `CommonModule` и лучше проверяется TypeScript .

- `@if (condition) { ... } @else { ... }` — условный вывод.
- `@for (item of items; track item.id) { ... } @empty { ... }` — цикл. **Обязательно** указывайте `track` (по `id` или самому примитиву), чтобы Angular мог переиспользовать DOM-элементы и не терять состояние (например, фокус в input) .

#### 2. Практика: Создание Todo-листа

Мы создадим компонент, который умеет добавлять и удалять задачи.

**Шаг 1: Генерация компонента**
```bash
ng generate component todo-list
```

**Шаг 2: Написание кода**

**`todo-list.component.ts`**
```typescript
import { Component } from '@angular/core';

// Интерфейс для одной задачи
interface Todo {
  id: number;
  text: string;
}

@Component({
  selector: 'app-todo-list',
  standalone: true,
  imports: [], // Пока ничего не импортируем
  templateUrl: './todo-list.component.html',
  styleUrl: './todo-list.component.css'
})
export class TodoListComponent {
  // Массив задач (в реальном приложении придет с сервера)
  todos: Todo[] = [
    { id: 1, text: 'Изучить Angular' },
    { id: 2, text: 'Сделать проект' }
  ];

  // Счетчик для уникальных ID новых задач
  private nextId = 3;

  // Метод для добавления задачи из input
  addTodo(input: HTMLInputElement) {
    const text = input.value.trim();
    if (!text) return; // Игнорируем пустой ввод

    // Добавляем новый объект в массив
    this.todos.push({ id: this.nextId++, text: text });
    
    // Очищаем поле ввода после добавления
    input.value = '';
  }

  // Метод удаления задачи по ID
  removeTodo(id: number) {
    // Фильтруем массив, оставляя все задачи кроме той, что нужно удалить
    this.todos = this.todos.filter(todo => todo.id !== id);
  }
}
```

**`todo-list.component.html`**
```html
<div class="todo-container">
  <h2>Мой список дел</h2>

  <!-- Блок добавления задачи -->
  <div class="add-row">
    <!-- Ссылочная переменная #taskInput позволяет получить доступ к элементу -->
    <input #taskInput type="text" placeholder="Новая задача..." 
           (keyup.enter)="addTodo(taskInput)">
    <!-- При клике передаем в метод сам input -->
    <button (click)="addTodo(taskInput)">Добавить</button>
  </div>

  <!-- Вывод списка задач (Новый синтаксис) -->
  <!-- track todo.id обязателен для производительности -->
  @for (todo of todos; track todo.id) {
    <div class="todo-item">
      <span>{{ todo.text }}</span>
      <!-- При клике передаем ID в метод удаления -->
      <button class="delete-btn" (click)="removeTodo(todo.id)">✕</button>
    </div>
  } @empty {
    <!-- Этот блок покажется, если массив todos пуст -->
    <p class="empty-msg">Список пуст. Добавьте первую задачу!</p>
  }
</div>
```

### Часть 4: Сервисы и Dependency Injection (DI)

**Цель:** Вынести данные и логику из компонента в переиспользуемый сервис.

#### 1. Теория: Зачем нужны Сервисы и DI

**Проблема:** Сейчас массив `todos` живёт внутри компонента. Если мы захотим создать второй компонент (например, «Статистика задач»), он не увидит этот массив. И если мы перезагрузим компонент, данные пропадут.

**Решение:** **Сервис** — это обычный TypeScript-класс, который хранит данные или логику. Angular использует **Dependency Injection (DI)**, чтобы «внедрить» (inject) этот сервис в компонент. Это позволяет разным частям приложения использовать один и тот же экземпляр сервиса (синглтон) .

**Ключевые понятия:**
- **`@Injectable({ providedIn: 'root' })`**: Декоратор, который говорит Angular: «Создай один экземпляр этого сервиса на всё приложение» .
- **`inject()`**: Современная функция для получения сервиса внутри компонента (рекомендуется вместо конструктора) .

#### 2. Практика: Перенос логики в `TodoService`

**Шаг 1: Генерация сервиса**
```bash
ng generate service todo
```
*CLI создаст файл `todo.service.ts` с декоратором `@Injectable`.*

**Шаг 2: Написание кода сервиса**

**`todo.service.ts`**
```typescript
import { Injectable } from '@angular/core';

// Экспортируем интерфейс, чтобы компоненты могли его импортировать
export interface Todo {
  id: number;
  text: string;
}

@Injectable({
  providedIn: 'root' // Сервис доступен во всём приложении как синглтон
})
export class TodoService {
  // Данные теперь живут здесь
  private todos: Todo[] = [
    { id: 1, text: 'Изучить Angular' },
    { id: 2, text: 'Сделать проект' }
  ];
  private nextId = 3;

  // Метод получения всех задач (возвращаем копию, чтобы не мутировали извне)
  getTodos(): Todo[] {
    return [...this.todos];
  }

  // Метод добавления
  addTodo(text: string): void {
    if (!text.trim()) return;
    this.todos.push({ id: this.nextId++, text: text.trim() });
  }

  // Метод удаления
  removeTodo(id: number): void {
    this.todos = this.todos.filter(todo => todo.id !== id);
  }
}
```

**Шаг 3: Обновление компонента (Внедрение сервиса)**

**`todo-list.component.ts`**
```typescript
import { Component, inject } from '@angular/core';
import { TodoService, Todo } from '../todo.service'; // Импорт сервиса и интерфейса

@Component({
  selector: 'app-todo-list',
  standalone: true,
  imports: [],
  templateUrl: './todo-list.component.html',
  styleUrl: './todo-list.component.css'
})
export class TodoListComponent {
  // Внедряем сервис через inject() — это современный и рекомендуемый способ
  private todoService = inject(TodoService);

  // Геттер для получения списка задач из сервиса
  // При каждом обращении в шаблоне будет вызываться getTodos()
  get todos(): Todo[] {
    return this.todoService.getTodos();
  }

  addTodo(input: HTMLInputElement) {
    this.todoService.addTodo(input.value);
    input.value = ''; // Очистка поля
  }

  removeTodo(id: number) {
    this.todoService.removeTodo(id);
  }
}
```

**Шаблон (`todo-list.component.html`)** менять почти не нужно, так как геттер `todos` возвращает актуальный список. Единственное — убедитесь, что в `@for` используется `track todo.id`.

**Что изменилось?**
1.  Логика работы с данными переехала в `TodoService`.
2.  Компонент стал «тонким» — он только принимает действия пользователя и передаёт их в сервис.
3.  Если мы создадим второй компонент, он тоже сможет сделать `inject(TodoService)` и получить тот же самый список задач.

#### 💡 Важные нюансы (Советы на будущее)

1.  **Возврат копии массива:** В `getTodos()` мы используем `[...this.todos]` (spread-оператор). Это защищает данные от случайного изменения из компонента. Если вернуть ссылку на оригинальный массив, компонент мог бы сделать `todos.push(...)` в обход методов сервиса.
2.  **`inject()` vs Конструктор:** Вы можете встретить старый способ `constructor(private todoService: TodoService) {}`. Он работает, но `inject()` считается более современным и гибким, особенно в связке с сигналами и функциями .
3.  **Обновление UI:** Сейчас при добавлении задачи массив в сервисе меняется, но Angular может не сразу «увидеть» это изменение, так как `getTodos()` возвращает новый массив при каждом вызове. В современном Angular для реактивности лучше использовать **Сигналы (`signal`)**, но это тема следующих дней. Пока текущая реализация будет работать при клике (из-за механизма Change Detection Angular), но для сложных случаев лучше переходить на сигналы.
