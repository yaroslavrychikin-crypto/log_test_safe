### Часть 5: Роутинг и Навигация

**Цель:** Превратить одностраничное приложение в многостраничное (SPA), научиться переключаться между компонентами без перезагрузки браузера.

#### 1. Теория: Как работает Angular Router

Angular Router — это мощная библиотека, которая сопоставляет URL-адреса с компонентами. Когда пользователь переходит по ссылке, Angular не запрашивает новую HTML-страницу у сервера, а подменяет компонент в специальном месте шаблона .

**Ключевые понятия:**
- **`Routes`**: Массив конфигурационных объектов. Каждый объект говорит: «Если URL совпадает с `path`, покажи этот `component`» .
- **`RouterOutlet`**: Директива-«дырка» в шаблоне. Именно сюда Angular вставляет компонент, соответствующий текущему маршруту .
- **`RouterLink`**: Директива для создания ссылок. Она заменяет обычный `href`, чтобы браузер не перезагружал страницу, а Angular перехватывал навигацию .

#### 2. Практика: Настройка маршрутизации

**Шаг 1: Создание компонентов для страниц**
Создадим две «страницы»: главную (Home) и «О нас» (About).
```bash
ng generate component home
ng generate component about
```
*Комментарий: CLI создаст папки с файлами компонентов. Они будут Standalone по умолчанию.*

**Шаг 2: Создание файла маршрутов**
В папке `src/app/` создайте файл `app.routes.ts`:
```typescript
import { Routes } from '@angular/router';
import { HomeComponent } from './home/home';
import { AboutComponent } from './about/about';

// Массив маршрутов. Порядок имеет значение: более специфичные пути должны идти выше.
export const routes: Routes = [
  { 
    path: '', // Пустой путь — это корень сайта (http://localhost:4200/)
    component: HomeComponent,
    title: 'Главная' // Устанавливает заголовок вкладки браузера
  },
  { 
    path: 'about', // Путь /about
    component: AboutComponent,
    title: 'О нас'
  },
  // Маршрут для перенаправления, если пользователь ввел несуществующий URL
  { 
    path: '**', // Wildcard: совпадает с любым путем
    redirectTo: '' // Перенаправляем на главную
  }
];
```
*Комментарий: `title` — полезная функция, которая автоматически меняет заголовок вкладки браузера при переходе.* 

**Шаг 3: Подключение маршрутизации в приложении**
Откройте `src/main.ts` (точка входа) и добавьте `provideRouter`:
```typescript
import { bootstrapApplication } from '@angular/platform-browser';
import { AppComponent } from './app/app.component';
import { provideRouter } from '@angular/router';
import { routes } from './app/app.routes';

bootstrapApplication(AppComponent, {
  providers: [
    provideRouter(routes) // Регистрируем маршруты в приложении
  ]
}).catch(err => console.error(err));
```
*Комментарий: `provideRouter` — это современный способ настройки роутера для Standalone-приложений. В старых проектах с NgModule использовался `RouterModule.forRoot(routes)`.* 

**Шаг 4: Настройка корневого компонента (навигация + outlet)**
Откройте `src/app/app.ts` и добавьте импорт `RouterOutlet` и `RouterLink`:
```typescript
import { Component } from '@angular/core';
import { RouterOutlet, RouterLink } from '@angular/router'; // Импортируем директивы

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet, RouterLink], // Добавляем в imports
  templateUrl: './app.component.html',
  styleUrl: './app.component.css'
})
export class AppComponent {
  title = 'my-app';
}
```

Теперь откройте `src/app/app.component.html` и создайте навигацию:
```html
<nav class="main-nav">
  <!-- routerLink — директива для навигации. Это аналог href, но без перезагрузки -->
  <a routerLink="/">Главная</a>
  <a routerLink="/about">О нас</a>
</nav>

<hr>

<!-- Сюда Angular будет вставлять компонент, соответствующий текущему URL -->
<router-outlet></router-outlet>
```
*Комментарий: `routerLink="/"` ведёт на корень. `routerLink="/about"` — на страницу About. При клике Angular перехватывает событие, меняет URL и отрисовывает нужный компонент в `<router-outlet>`.* 

**Шаг 5: Проверка**
Запустите `ng serve`. Вы должны увидеть меню. При клике на «О нас» контент под меню меняется, а URL в адресной строке обновляется на `/about`. Перезагрузки страницы не происходит.

### Часть 6: Работа с API (HttpClient)

**Цель:** Научиться получать данные с внешнего сервера и отображать их в приложении.

#### 1. Теория: HttpClient и Observable

Современные веб-приложения почти всегда общаются с сервером. Angular предоставляет сервис `HttpClient` для выполнения HTTP-запросов .

**Ключевой момент:** Методы `HttpClient` (get, post и т.д.) возвращают **`Observable`** — объект из библиотеки RxJS. Чтобы запрос действительно выполнился и данные пришли, на этот Observable нужно **подписаться** (вызвать `.subscribe()`). Без подписки запрос не уйдёт .

#### 2. Практика: Получение списка постов

Мы будем использовать публичный API `jsonplaceholder.typicode.com`, который не требует ключей и возвращает тестовые данные.

**Шаг 1: Подключение HttpClient**
Откройте `src/main.ts` и добавьте `provideHttpClient`:
```typescript
import { provideHttpClient } from '@angular/common/http'; // Импорт

bootstrapApplication(AppComponent, {
  providers: [
    provideRouter(routes),
    provideHttpClient() // Регистрируем HttpClient в приложении
  ]
}).catch(err => console.error(err));
```
*Комментарий: В Standalone-приложениях `HttpClient` подключается именно через `provideHttpClient()`.* 

**Шаг 2: Создание сервиса для работы с API**
Создайте сервис `post`:
```bash
ng generate service post
```

**`post.service.ts`**
```typescript
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

// Интерфейс описывает структуру данных, которые мы ожидаем от API
export interface Post {
  userId: number;
  id: number;
  title: string;
  body: string;
}

@Injectable({
  providedIn: 'root'
})
export class PostService {
  // Внедряем HttpClient через inject()
  private http = inject(HttpClient);
  
  // Базовый URL API
  private apiUrl = 'https://jsonplaceholder.typicode.com/posts';

  // Метод возвращает Observable, а не сами данные.
  // Запрос выполнится только когда кто-то подпишется на этот Observable.
  getPosts(): Observable<Post[]> {
    return this.http.get<Post[]>(this.apiUrl);
  }
}
```
*Комментарий: `http.get<Post[]>` — обобщённый тип. Мы говорим TypeScript: «Ожидаем массив объектов Post». Это даёт автодополнение и проверку типов.* 

**Шаг 3: Использование сервиса в компоненте**
Создайте компонент `posts-list`:
```bash
ng generate component posts-list
```

**`posts-list.component.ts`**
```typescript
import { Component, inject, OnInit } from '@angular/core';
import { PostService, Post } from '../post.service';

@Component({
  selector: 'app-posts-list',
  standalone: true,
  imports: [],
  templateUrl: './posts-list.component.html',
  styleUrl: './posts-list.component.css'
})
export class PostsListComponent implements OnInit {
  private postService = inject(PostService);
  
  // Массив для хранения полученных постов
  posts: Post[] = [];
  
  // Переменные для состояний загрузки и ошибки
  isLoading = true;
  errorMessage = '';

  // ngOnInit — lifecycle hook, вызывается после создания компонента
  ngOnInit(): void {
    // Подписываемся на Observable, чтобы запрос выполнился
    this.postService.getPosts().subscribe({
      next: (data) => {
        // next вызывается, когда данные успешно пришли
        this.posts = data;
        this.isLoading = false;
      },
      error: (err) => {
        // error вызывается при проблемах с сетью или сервером
        this.errorMessage = 'Не удалось загрузить посты. Проверьте соединение.';
        this.isLoading = false;
        console.error('Ошибка загрузки:', err);
      }
    });
  }
}
```
*Комментарий: Мы подписываемся в `ngOnInit`, чтобы запрос начался сразу после создания компонента. `next` и `error` — это колбэки для успешного и неуспешного сценария.* 

**Шаг 4: Отображение данных в шаблоне**
**`posts-list.component.html`**
```html
<div class="posts-container">
  <h2>Список постов</h2>

  <!-- Состояние загрузки -->
  @if (isLoading) {
    <p class="loading">Загрузка...</p>
  }

  <!-- Состояние ошибки -->
  @if (errorMessage) {
    <p class="error">{{ errorMessage }}</p>
  }

  <!-- Список постов. @for используется вместо *ngFor -->
  @for (post of posts; track post.id) {
    <div class="post-card">
      <h3>{{ post.title }}</h3>
      <p>{{ post.body }}</p>
      <small>ID: {{ post.id }}</small>
    </div>
  } @empty {
    <!-- Если массив пуст (например, пришли пустые данные) -->
    @if (!isLoading && !errorMessage) {
      <p>Постов пока нет.</p>
    }
  }
</div>
```

**Шаг 5: Добавление маршрута для страницы постов**
Обновите `app.routes.ts`:
```typescript
import { PostsListComponent } from './posts-list/posts-list.component';

export const routes: Routes = [
  { path: '', component: HomeComponent, title: 'Главная' },
  { path: 'about', component: AboutComponent, title: 'О нас' },
  { path: 'posts', component: PostsListComponent, title: 'Посты' }, // Новый маршрут
  { path: '**', redirectTo: '' }
];
```
И добавьте ссылку в навигацию `app.component.html`:
```html
<a routerLink="/posts">Посты</a>
```

**Результат:** При переходе на `/posts` вы увидите индикатор загрузки, затем список из 100 постов, полученных с реального API.

#### 💡 Важные нюансы (Советы на будущее)

1.  **Всегда отписывайтесь:** В нашем примере `HttpClient` автоматически завершает Observable после получения ответа, поэтому утечки памяти не будет. Но для других Observable (например, событий) нужно использовать `takeUntilDestroyed` или отписываться вручную.
2.  **Не вызывайте методы в шаблоне:** Если написать `{{ postService.getPosts() }}` прямо в HTML, запрос будет уходить при каждом цикле Change Detection. Всегда сохраняйте данные в свойство компонента, как мы сделали с `posts`.
3.  **`ActivatedRoute` для параметров:** Если бы у нас был маршрут `/posts/:id`, мы бы использовали сервис `ActivatedRoute`, чтобы получить `id` из URL и загрузить конкретный пост .
