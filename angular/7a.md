## Часть 7: Формы и Сборка проекта

**Цель:** Научиться принимать и валидировать ввод от пользователя, а затем собрать оптимизированную версию приложения для продакшена.

---

### 1. Теория: Два подхода к формам в Angular

Angular предлагает два принципиально разных подхода к работе с формами. Понимание разницы между ними — ключ к правильному выбору инструмента.

**Template-driven формы (на основе шаблона)**
Здесь «источником истины» является сам HTML-шаблон. Вы используете директиву `[(ngModel)]` для двусторонней привязки, и Angular автоматически создаёт и управляет моделью формы под капотом . Этот подход хорош для простых форм с минимальной логикой.

**Reactive формы (реактивные)**
Здесь «источником истины» является класс компонента. Вы явно создаёте модель формы (`FormGroup`, `FormControl`) в TypeScript, а шаблон лишь связывается с ней через `[formGroup]` и `formControlName` . Это даёт полный контроль над валидацией, состоянием и значениями, что делает подход предпочтительным для сложных и enterprise-приложений .

**Для части 7 мы будем использовать Reactive формы**, так как они дают более наглядное понимание того, как Angular управляет состоянием, и лучше готовят к реальной работе.

### 2. Практика: Форма создания поста с валидацией

Мы создадим форму, которая имитирует добавление нового поста в наш список (из Дня 6). Форма будет требовать заголовок и текст, а кнопка «Отправить» будет неактивна, пока форма невалидна.

#### Шаг 1: Подготовка компонента

Создайте новый компонент (или используйте существующий):
```bash
ng generate component post-form
```

#### Шаг 2: Написание кода (Файлы с комментариями)

**`post-form.ts` (Логика формы)**
```typescript
import { Component, inject } from '@angular/core';
import { 
  FormBuilder,        // Сервис для удобного создания форм
  FormGroup,          // Группа контролов (сама форма)
  ReactiveFormsModule, // Модуль, необходимый для работы с реактивными формами
  Validators          // Встроенные валидаторы (required, minLength и т.д.)
} from '@angular/forms';

@Component({
  selector: 'app-post-form',
  standalone: true,
  imports: [ReactiveFormsModule], // Обязательно импортируем для standalone-компонента
  templateUrl: './post-form.html',
  styleUrl: './post-form.css'
})
export class PostFormComponent {
  // Внедряем FormBuilder для декларативного создания формы
  private fb = inject(FormBuilder);

  // Создаём модель формы. Каждый контрол — это поле ввода.
  // Первое значение в массиве — начальное (пустая строка).
  // Второе — массив валидаторов.
  postForm: FormGroup = this.fb.group({
    title: ['', [Validators.required, Validators.minLength(3)]],
    body: ['', [Validators.required, Validators.minLength(10)]]
  });

  // Геттер для удобного доступа к контролам в шаблоне (для отображения ошибок)
  get title() { return this.postForm.get('title'); }
  get body() { return this.postForm.get('body'); }

  // Метод, вызываемый при отправке формы
  onSubmit() {
    // Проверяем, валидна ли форма, прежде чем что-то делать
    if (this.postForm.valid) {
      // В реальном приложении здесь был бы вызов сервиса для отправки на сервер
      console.log('Отправленные данные:', this.postForm.value);
      
      // Сброс формы после "отправки"
      this.postForm.reset();
    } else {
      // Если форма невалидна, помечаем все поля как "тронутые",
      // чтобы пользователь увидел сообщения об ошибках
      this.postForm.markAllAsTouched();
    }
  }
}
```

**`post-form.html` (Шаблон с валидацией)**
```html
<div class="form-container">
  <h2>Создать пост</h2>

  <!-- [formGroup] связывает HTML-форму с нашей моделью postForm -->
  <!-- (ngSubmit) вызывает метод onSubmit при отправке -->
  <form [formGroup]="postForm" (ngSubmit)="onSubmit()">
    
    <!-- Поле ЗАГОЛОВКА -->
    <div class="form-group">
      <label for="title">Заголовок</label>
      <!-- formControlName связывает этот input с контролом 'title' в форме -->
      <input 
        id="title" 
        type="text" 
        formControlName="title"
        placeholder="Введите заголовок (мин. 3 символа)"
      >
      
      <!-- Блок ошибок. Показывается, ТОЛЬКО если поле 'title' невалидно 
           И пользователь его уже "тронул" (пытался взаимодействовать) -->
      @if (title?.invalid && title?.touched) {
        <div class="error">
          @if (title?.errors?.['required']) {
            <small>Заголовок обязателен</small>
          }
          @if (title?.errors?.['minlength']) {
            <small>Минимум 3 символа</small>
          }
        </div>
      }
    </div>

    <!-- Поле ТЕКСТА -->
    <div class="form-group">
      <label for="body">Текст поста</label>
      <textarea 
        id="body" 
        formControlName="body"
        rows="4"
        placeholder="Введите текст (мин. 10 символов)"
      ></textarea>
      
      @if (body?.invalid && body?.touched) {
        <div class="error">
          @if (body?.errors?.['required']) {
            <small>Текст обязателен</small>
          }
          @if (body?.errors?.['minlength']) {
            <small>Минимум 10 символов</small>
          }
        </div>
      }
    </div>

    <!-- Кнопка отправки -->
    <!-- [disabled]="postForm.invalid" делает кнопку неактивной,
         пока вся форма не пройдёт валидацию -->
    <button type="submit" [disabled]="postForm.invalid">
      Отправить
    </button>
    
    <!-- Дополнительно: показываем текущее состояние формы для отладки -->
    <p class="debug">
      Статус формы: <strong>{{ postForm.valid ? 'Валидна' : 'Невалидна' }}</strong>
    </p>
  </form>
</div>
```

#### Шаг 3: Интеграция в приложение

Добавьте компонент в маршруты (`app.routes.ts`) или просто разместите его на главной странице (`app.html`), чтобы увидеть результат.

**Что вы должны увидеть:**
1.  Поля ввода пустые, кнопка «Отправить» **неактивна** (потому что `Validators.required` не выполнен).
2.  Если начать вводить текст в заголовок и стереть его, поле подсветится красным и появится сообщение «Заголовок обязателен» (потому что поле стало `touched`).
3.  Как только оба поля будут заполнены корректно (заголовок ≥ 3 символов, текст ≥ 10), кнопка станет активной.
4.  При нажатии «Отправить» в консоль выведется объект с введёнными данными, а форма очистится.

### 3. Теория: Сборка проекта (Build)

Когда приложение готово, его нужно собрать для размещения на сервере. Команда `ng serve` запускает **dev-сервер** для разработки (с проверками и без оптимизации), а `ng build` создаёт **готовые файлы** в папке `dist/`.

**Что делает продакшен-сборка:**
- **AOT-компиляция:** Шаблоны компилируются в JavaScript на этапе сборки, а не в браузере.
- **Минификация:** Удаляются пробелы, комментарии, длинные имена переменных заменяются на короткие.
- **Tree-shaking:** Удаляется неиспользуемый код.
- **Бандлинг:** Файлы объединяются в несколько бандлов для быстрой загрузки .

#### Практика: Сборка

В терминале, в папке проекта, выполните:
```bash
ng build --configuration production
```
*Комментарий: Флаг `--configuration production` (или сокращённо `-c production`) включает все оптимизации .*

После завершения команды в папке проекта появится директория `dist/`. Внутри неё будут файлы `main.[hash].js`, `styles.[hash].css` и `index.html`. Именно **содержимое папки `dist/`** вы выкладываете на хостинг (например, Firebase Hosting, Netlify, Vercel или обычный сервер).

Вы также можете проверить собранную версию локально. Для этого установите простой статический сервер (если его нет):
```bash
npx http-server dist/my-app/browser
```
*(Путь может отличаться в зависимости от версии Angular. Проверьте содержимое папки `dist`.)*

### 💡 Важные нюансы (Советы на будущее)

1.  **`markAllAsTouched()`:** Этот метод в `onSubmit` нужен, чтобы сообщения об ошибках появились, даже если пользователь просто нажал «Отправить», не трогая поля. Без него невалидная форма просто не отправится, а пользователь не поймёт, почему.
2.  **`FormBuilder` vs `new FormGroup`:** `FormBuilder` — это удобная обёртка. Запись `this.fb.group({...})` короче и читаемее, чем `new FormGroup({ title: new FormControl(...) })`.
3.  **Не забывайте про `ReactiveFormsModule`:** Если вы используете `[formGroup]` в Standalone-компоненте, но забыли добавить `ReactiveFormsModule` в `imports`, Angular выдаст ошибку о неизвестной директиве.
