# Работа с интернетом в Linux: подробное практическое руководство

В Linux настройка доступа в интернет и управление сетью осуществляются через несколько уровней: от низкоуровневых команд `ip` до высокоуровневых менеджеров вроде `NetworkManager`. Понимание этих инструментов критично, так как в разных дистрибутивах (Ubuntu, Debian, CentOS, Astra Linux) используются разные подходы к сохранению конфигурации.

Ниже — максимально подробный разбор с практическими примерами и комментариями к каждой команде.

---

## 1. Диагностика: с чего начать проверку

Прежде чем что-то настраивать, нужно понять текущее состояние сети. Базовый набор инструментов доступен в большинстве систем.

### Проверка интерфейсов и IP-адресов

```bash
# Показать все сетевые интерфейсы с IP-адресами (современный способ)
ip addr show

# Краткий формат (удобно для быстрого взгляда)
ip -br a
```

**Комментарий:** `ip` — это современная замена устаревшему `ifconfig`. Вывод покажет интерфейсы (`lo`, `eth0`, `enp0s3` и т.д.), их состояние (`UP`/`DOWN`), MAC-адрес и назначенные IP.

```bash
# Показать таблицу маршрутизации (куда уходит трафик)
ip route show

# Проверить, какой маршрут будет выбран для конкретного адреса
ip route get 8.8.8.8
```

**Комментарий:** Если в таблице маршрутов нет строки `default via ...`, значит шлюз по умолчанию не задан, и интернет работать не будет (даже если IP есть).

### Проверка связности

```bash
# Проверить доступность внешнего ресурса по IP (4 пакета и остановка)
ping -c 4 8.8.8.8

# Проверить разрешение доменных имён (если ping по IP идёт, а по имени — нет, проблема в DNS)
ping -c 4 google.com

# Трассировка маршрута до узла (показывает, на каком хопе теряется связь)
traceroute -n 8.8.8.8
```

**Комментарий:** `-c 4` ограничивает количество пакетов, чтобы команда не работала бесконечно. `-n` в `traceroute` отключает DNS-резолвинг, ускоряя вывод.

## 2. Настройка через NetworkManager (`nmcli`) — основной метод для десктопов и многих серверов

`NetworkManager` — это служба, которая управляет сетевыми подключениями и автоматически применяет настройки. `nmcli` — её командный интерфейс. Этот способ рекомендуется для систем с графическим интерфейсом и большинства современных серверных дистрибутивов (Ubuntu, Fedora, RHEL, Astra Linux).

### Просмотр текущих подключений

```bash
# Список всех сохранённых профилей подключений
nmcli connection show

# Список устройств и их состояние (подключено/отключено)
nmcli device status
```

**Комментарий:** `connection show` показывает профили (например, `Wired connection 1` или `enp0s3`), а `device status` — физические интерфейсы. Профиль может быть сохранён, но не активен.

### Настройка статического IP (самый частый сценарий для сервера)

Предположим, интерфейс называется `enp0s3`, и мы хотим задать:
- IP: `192.168.1.200/24`
- Шлюз: `192.168.1.1`
- DNS: `8.8.8.8` и `1.1.1.1`

```bash
# Изменяем профиль подключения enp0s3
nmcli connection modify enp0s3 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.200/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "8.8.8.8 1.1.1.1" \
  connection.autoconnect yes
```

**Комментарий к параметрам:**
- `ipv4.method manual` — отключает DHCP и говорит, что адрес задаётся вручную.
- `ipv4.addresses` — можно указать несколько адресов через запятую, если нужно.
- `ipv4.dns` — список DNS-серверов через пробел (в кавычках).
- `connection.autoconnect yes` — поднимать соединение при загрузке системы (важно для серверов).

```bash
# Применяем изменения: перезапускаем подключение
nmcli connection down enp0s3
nmcli connection up enp0s3
```

**Комментарий:** Без перезапуска (down/up) изменения не вступят в силу. На удалённом сервере выполняйте обе команды в одной строке через `;`, чтобы не потерять SSH-сессию, если что-то пойдёт не так:
```bash
nmcli con down enp0s3; nmcli con up enp0s3
```

### Переключение обратно на DHCP

```bash
nmcli connection modify enp0s3 ipv4.method auto
nmcli connection down enp0s3; nmcli connection up enp0s3
```

**Комментарий:** `auto` означает «получить настройки автоматически». Если вы ранее задавали статический DNS и хотите снова получать DNS от DHCP-сервера, добавьте `ipv4.ignore-auto-dns no`.

### Частный случай: DHCP, но свой DNS

```bash
nmcli connection modify enp0s3 \
  ipv4.method auto \
  ipv4.ignore-auto-dns yes \
  ipv4.dns "192.168.1.100"
```

**Комментарий:** IP-адрес и шлюз придут по DHCP, но DNS-серверы будут принудительно использоваться указанные вами. Это полезно, если провайдерский DNS работает медленно или блокирует запросы.

## 3. Настройка через `ip` (временная, «здесь и сейчас»)

Команды `ip` изменяют состояние ядра напрямую. Они **не сохраняются** после перезагрузки и не управляются NetworkManager (если только вы не отключили его для этого интерфейса). Используются для быстрой проверки или в скриптах.

```bash
# Назначить IP-адрес интерфейсу eth0 (добавляется к существующим)
sudo ip addr add 192.168.1.100/24 dev eth0

# Удалить IP-адрес
sudo ip addr del 192.168.1.100/24 dev eth0

# Включить интерфейс (если он был DOWN)
sudo ip link set eth0 up

# Выключить интерфейс
sudo ip link set eth0 down

# Добавить шлюз по умолчанию
sudo ip route add default via 192.168.1.1 dev eth0

# Удалить шлюз по умолчанию
sudo ip route del default
```

**Комментарий:** После `ip addr add` интерфейс должен быть в состоянии `UP`, иначе адрес не будет работать. Если вы настраиваете сервер удалённо, сначала добавьте адрес, затем убедитесь, что старый не потерян, и только потом меняйте маршрут.

## 4. Постоянная настройка в разных дистрибутивах (файлы конфигурации)

### Ubuntu / Debian (Netplan — современный стандарт)

В Ubuntu 18.04+ и свежих Debian используется Netplan. Файлы лежат в `/etc/netplan/` (обычно `01-netcfg.yaml` или `50-cloud-init.yaml`).

Пример конфигурации для статического IP:

```yaml
network:
  version: 2
  ethernets:
    enp6s0:
      dhcp4: false
      addresses:
        - 172.16.0.1/24
      routes:
        - to: default
          via: 172.16.0.254
      nameservers:
        addresses:
          - 172.16.0.254
          - 8.8.8.8
```

**Комментарий:** Отступы в YAML критичны — используйте пробелы, не табы. После редактирования примените конфигурацию:

```bash
sudo netplan apply
```

**Комментарий:** Если `netplan apply` выдаёт ошибку синтаксиса, проверьте отступы. Для отладки можно выполнить `sudo netplan --debug apply`.

### CentOS / RHEL / Rocky Linux (классические ifcfg-файлы)

Файлы находятся в `/etc/sysconfig/network-scripts/ifcfg-<интерфейс>`.

Пример для `ifcfg-eth0`:

```bash
DEVICE=eth0
BOOTPROTO=static
ONBOOT=yes
IPADDR=192.168.1.100
NETMASK=255.255.255.0
GATEWAY=192.168.1.1
DNS1=8.8.8.8
DNS2=8.8.4.4
```

**Комментарий:** `BOOTPROTO=static` (или `none` в некоторых версиях) означает статику. `ONBOOT=yes` — поднимать при загрузке. После редактирования перезапустите сеть:

```bash
sudo systemctl restart network
```

**Комментарий:** В RHEL 8+ и CentOS 8+ по умолчанию используется NetworkManager с `nmcli`, но классические ifcfg-файлы всё ещё поддерживаются.

### Debian / Astra Linux (старый стиль `/etc/network/interfaces`)

Некоторые системы (Astra Linux, старые Debian) используют `ifupdown`.

```bash
allow-hotplug eth0
iface eth0 inet static
    address 192.168.11.100
    netmask 255.255.255.0
    gateway 192.168.11.1
    dns-nameservers 192.168.11.100
```

**Комментарий:** Для применения изменений используйте:
```bash
sudo ifdown eth0; sudo ifup eth0
```
**Важно:** Не смешивайте `ifupdown` и `NetworkManager` на одном интерфейсе — это приводит к конфликтам. Если вы используете `nmcli`, не редактируйте `/etc/network/interfaces` для того же интерфейса.

## 5. DNS: отдельный уровень настройки

Даже при работающем IP интернет может не работать, если не резолвятся домены. В Linux DNS настраивается на нескольких уровнях, и они могут конфликтовать.

### Быстрая проверка: какой DNS используется сейчас

```bash
cat /etc/resolv.conf
```

**Комментарий:** Если там `nameserver 127.0.0.53`, значит используется `systemd-resolved` (заглушка). Реальные серверы смотрите через `resolvectl status` или `resolvectl dns`.

### Настройка DNS через NetworkManager (рекомендуется для десктопов)

```bash
nmcli connection modify enp0s3 ipv4.dns "8.8.8.8 1.1.1.1"
nmcli connection down enp0s3; nmcli connection up enp0s3
```

**Комментарий:** Этот способ переживает перезагрузку и не конфликтует с другими службами.

### Настройка через `systemd-resolved` (Ubuntu/Debian/Fedora)

```bash
sudo nano /etc/systemd/resolved.conf
```

Раскомментируйте и измените строку `DNS`:

```ini
[Resolve]
DNS=8.8.8.8 1.1.1.1
FallbackDNS=9.9.9.9
```

```bash
sudo systemctl restart systemd-resolved
```

**Комментарий:** `FallbackDNS` используются, если основные серверы недоступны. Проверить результат: `resolvectl status`.

### Временное изменение `/etc/resolv.conf`

```bash
sudo nano /etc/resolv.conf
```

Добавьте:
```
nameserver 8.8.8.8
nameserver 1.1.1.1
```

**Комментарий:** Это **временное** решение. При перезагрузке или перезапуске сети файл будет перезаписан (`systemd-resolved` или `NetworkManager`). Используйте только для быстрой диагностики.

## 6. Диагностика проблем: пошаговый алгоритм

Если интернет не работает, двигайтесь по уровням.

### Шаг 1: Есть ли IP и шлюз?

```bash
ip -br a
ip route show
```

Если IP нет — проблема на уровне интерфейса (не поднят, не настроен). Если IP есть, но нет `default via` — проблема с шлюзом.

### Шаг 2: Доступен ли шлюз?

```bash
ping -c 3 192.168.1.1
```

**Комментарий:** Если шлюз не пингуется, проблема в локальной сети (кабель, VLAN, коммутатор). Если пингуется — двигаемся дальше.

### Шаг 3: Доступен ли внешний IP?

```bash
ping -c 3 8.8.8.8
```

Если 8.8.8.8 не пингуется, но шлюз доступен — проблема у провайдера или в настройках NAT/маршрутизации.

### Шаг 4: Работает ли DNS?

```bash
ping -c 3 google.com
```

Если `8.8.8.8` пингуется, а `google.com` — нет, проблема в DNS. Проверьте `cat /etc/resolv.conf` и `resolvectl status`.

### Шаг 5: Слушает ли служба нужный порт?

```bash
# Показать все слушающие TCP-порты с именами процессов
ss -tlpn
```

**Комментарий:** `ss` — современная замена `netstat`. Параметры: `-t` TCP, `-l` listening, `-p` процессы, `-n` числовые порты (без резолва имён). Если нужный сервис (например, SSH на 22) не отображается — он не запущен или слушает только localhost.

### Шаг 6: Проверка файрвола

```bash
# Для систем с ufw (Ubuntu)
sudo ufw status verbose

# Для систем с firewalld (CentOS/RHEL)
sudo firewall-cmd --list-all

# Для iptables напрямую
sudo iptables -L INPUT -n -v
```

**Комментарий:** Если порт заблокирован файрволом, подключение снаружи не установится, даже если служба работает. Для ufw разрешить порт: `sudo ufw allow 22/tcp`.

## 7. Продвинутый пример: VLAN через `nmcli`

VLAN позволяет разделить трафик на одном физическом интерфейсе. Пример создания VLAN 100 на интерфейсе `enp0s3`:

```bash
nmcli connection add type vlan \
  con-name vlan-enp0s3.100 \
  ifname enp0s3.100 \
  dev enp0s3 \
  id 100 \
  ip4 10.10.1.10/24
```

**Комментарий к параметрам:**
- `type vlan` — создаём VLAN-интерфейс.
- `ifname enp0s3.100` — имя виртуального интерфейса (обычно `<родитель>.<id>`).
- `dev enp0s3` — физический интерфейс, поверх которого создаётся VLAN.
- `id 100` — VLAN ID.
- `ip4` — сразу назначаем IP.

Проверка:
```bash
ip -br a | grep vlan
ping -I enp0s3.100 10.10.1.1
```

**Комментарий:** `ping -I` указывает, с какого интерфейса отправлять пакеты. Это полезно для проверки, что VLAN действительно работает и трафик тегируется.

## Итоговая рекомендация по выбору метода

| Ситуация | Инструмент |
|---|---|
| Десктоп или сервер с NetworkManager | `nmcli` (сохраняется, управляемо) |
| Быстрая проверка / скрипт | `ip addr` / `ip route` (временно) |
| Ubuntu 18.04+ / современный Debian | Netplan (YAML в `/etc/netplan/`) |
| CentOS/RHEL 7 | `ifcfg-*` в `/etc/sysconfig/network-scripts/` |
| Astra Linux / старый Debian | `/etc/network/interfaces` + `ifupdown` |
| Диагностика DNS | `resolvectl` / `dig` / `nslookup` |

Главное правило: **не смешивайте инструменты** на одном интерфейсе. Если вы настроили интерфейс через `nmcli`, не редактируйте для него же `/etc/network/interfaces` — это приведёт к непредсказуемому поведению при загрузке.
