# Полный гайд по работе с SQL в PostgreSQL: от создания таблиц до INSERT/UPDATE/DELETE

Это руководство охватывает путь от создания таблиц с ограничениями до уверенного владения командами изменения данных (DML) в PostgreSQL.

---

## Шаг 1: Создание тестовой таблицы

Для демонстрации команд нам нужна таблица. Создадим простую таблицу `products`, которая будет хранить товары.

```sql
-- Создаём таблицу products с четырьмя столбцами
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,  -- Автоинкрементный первичный ключ (уникальный ID)
    name TEXT NOT NULL,             -- Название товара, обязательное поле
    price NUMERIC(10, 2),           -- Цена с двумя знаками после запятой
    category TEXT                   -- Категория товара
);
```

**Комментарии к коду:**
- `SERIAL`: это псевдотип в PostgreSQL, который автоматически создаёт последовательность (sequence) для генерации уникальных целых чисел. Идеально подходит для ID.
- `PRIMARY KEY`: ограничение, которое делает столбец уникальным и не допускает значений NULL.
- `NOT NULL`: гарантирует, что в этом столбце всегда будет значение.
- `NUMERIC(10, 2)`: тип данных для точных чисел. 10 — общее количество цифр, 2 — количество цифр после запятой.

## Шаг 2: Ограничения (constraints) при создании таблиц

Ограничения — это правила, которые база данных применяет автоматически, чтобы не допустить попадания в таблицы логически некорректных данных. Если `INSERT` или `UPDATE` попытается нарушить ограничение, PostgreSQL отклонит операцию целиком и вернёт ошибку.

Ограничения можно задавать двумя способами: **как часть определения столбца** (column constraint) или **как отдельное определение таблицы** (table constraint). Второй способ необходим, когда ограничение затрагивает несколько столбцов сразу.

### 2.1. NOT NULL — запрет пустых значений

Самое простое ограничение. Оно гарантирует, что в столбце всегда будет какое-то значение, а не `NULL` (что в SQL означает «неизвестно»).

```sql
CREATE TABLE users (
    user_id SERIAL PRIMARY KEY,
    username TEXT NOT NULL,          -- имя пользователя обязательно
    email TEXT NOT NULL,
    bio TEXT                         -- описание может быть пустым (NULL)
);
```

**Комментарий:** `NOT NULL` — это ограничение столбца. Оно проверяется при каждой вставке или обновлении. Если попытаться вставить строку без `username`, PostgreSQL выдаст ошибку.

### 2.2. UNIQUE — уникальность значений

Гарантирует, что значения в столбце (или комбинации столбцов) не повторяются.

```sql
-- Вариант 1: ограничение на один столбец
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    product_code TEXT UNIQUE,        -- артикул не должен повторяться
    name TEXT NOT NULL
);

-- Вариант 2: именованное ограничение (для понятных сообщений об ошибках)
CREATE TABLE accounts (
    account_id SERIAL PRIMARY KEY,
    email TEXT CONSTRAINT must_be_unique_email UNIQUE
);

-- Вариант 3: составное ограничение (комбинация столбцов уникальна)
CREATE TABLE warehouse_slots (
    warehouse_id INT,
    slot_number INT,
    capacity INT,
    UNIQUE (warehouse_id, slot_number)  -- в одном складе номер ячейки уникален
);
```

**Важный нюанс PostgreSQL:** два значения `NULL` **не считаются равными** при проверке `UNIQUE`. Это значит, что в столбец с ограничением `UNIQUE` можно вставить сколько угодно строк со значением `NULL` (если столбец не помечен как `NOT NULL`). Это соответствует стандарту SQL, но может отличаться от поведения других СУБД.

**Техническая деталь:** при добавлении `UNIQUE` PostgreSQL автоматически создаёт уникальный B-tree индекс, который ускоряет поиск и обеспечивает проверку.

### 2.3. PRIMARY KEY — первичный ключ

Первичный ключ — это комбинация `UNIQUE` + `NOT NULL`. Он однозначно идентифицирует каждую строку в таблице.

```sql
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,     -- обычно SERIAL + PRIMARY KEY
    order_date DATE NOT NULL,
    customer_id INT NOT NULL
);

-- Составной первичный ключ (когда одна колонка не может быть уникальным идентификатором)
CREATE TABLE order_items (
    order_id INT,
    product_id INT,
    quantity INT NOT NULL,
    PRIMARY KEY (order_id, product_id)  -- пара (заказ, товар) уникальна
);
```

**Ключевые факты о PRIMARY KEY:**
- Таблица может иметь **не более одного** первичного ключа (в отличие от `UNIQUE`, которых может быть много).
- Первичный ключ автоматически создаёт уникальный индекс и принудительно делает столбцы `NOT NULL`.
- Если в другой таблице есть внешний ключ, он по умолчанию ссылается именно на первичный ключ указанной таблицы.

### 2.4. FOREIGN KEY — ссылочная целостность

Внешний ключ гарантирует, что значение в столбце одной таблицы (дочерней) существует в другой таблице (родительской). Это основа связей между таблицами.

```sql
-- Родительская таблица
CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    name TEXT NOT NULL
);

-- Дочерняя таблица
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    customer_id INT REFERENCES customers (customer_id),  -- ссылка на customers
    order_date DATE NOT NULL
);
```

**Сокращённая запись:** если опустить имя столбца в скобках, PostgreSQL будет ссылаться на первичный ключ родительской таблицы:
```sql
customer_id INT REFERENCES customers  -- эквивалентно REFERENCES customers (customer_id)
```

**Поведение при удалении/обновлении родительской строки:** по умолчанию PostgreSQL **запрещает** удалять или изменять строку в родительской таблице, если на неё есть ссылки. Это можно изменить с помощью `ON DELETE` и `ON UPDATE`:

```sql
CREATE TABLE order_items (
    item_id SERIAL PRIMARY KEY,
    order_id INT REFERENCES orders (order_id) ON DELETE CASCADE,
    product_id INT,
    quantity INT
);
```

- `ON DELETE CASCADE` — при удалении заказа автоматически удалятся все его позиции.
- `ON DELETE SET NULL` — при удалении заказа в поле `order_id` дочерней строки запишется `NULL`.
- `ON DELETE RESTRICT` / `NO ACTION` — запретить удаление (поведение по умолчанию).
- `ON UPDATE CASCADE` — при изменении ключа в родительской таблице он автоматически обновится в дочерней.

**Ссылка на себя (self-referential):** внешний ключ может ссылаться на ту же таблицу. Классический пример — древовидная структура:

```sql
CREATE TABLE categories (
    category_id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    parent_id INT REFERENCES categories (category_id)  -- ссылка на эту же таблицу
);
```
Корневая категория будет иметь `parent_id = NULL`, а остальные — ссылаться на вышестоящую категорию.

### 2.5. CHECK — проверка произвольного условия

Позволяет задать логическое выражение, которое должно быть истинным для каждой строки. Если выражение возвращает `FALSE`, операция отклоняется.

```sql
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    price NUMERIC(10, 2) CHECK (price > 0),           -- цена должна быть положительной
    discount NUMERIC(5, 2) CHECK (discount >= 0 AND discount <= 100),
    stock INT CHECK (stock >= 0)                       -- остаток не может быть отрицательным
);
```

**Ограничение уровня таблицы** (когда условие затрагивает несколько столбцов):
```sql
CREATE TABLE events (
    event_id SERIAL PRIMARY KEY,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    CHECK (end_date >= start_date)  -- дата окончания не может быть раньше даты начала
);
```

**Именованные ограничения** для понятных сообщений об ошибках:
```sql
CREATE TABLE accounts (
    account_id SERIAL PRIMARY KEY,
    balance NUMERIC(12, 2) CONSTRAINT positive_balance CHECK (balance >= 0)
);
```
Если попытаться записать отрицательный баланс, ошибка будет содержать имя `positive_balance`, что упрощает отладку.

**Важно:** `CHECK` не должен содержать подзапросы или ссылаться на другие строки таблицы. Он проверяется только для текущей вставляемой/обновляемой строки.

### 2.6. DEFAULT — значение по умолчанию (не совсем ограничение, но важно)

Хотя технически `DEFAULT` не является ограничением, он тесно связан с ними, определяя, что записывается в столбец, если значение не указано.

```sql
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    status TEXT DEFAULT 'new',                -- по умолчанию статус "новый"
    created_at TIMESTAMP DEFAULT NOW(),       -- автоматически текущее время
    quantity INT DEFAULT 1 CHECK (quantity > 0)
);
```

### 2.7. Как работают ограничения вместе: пример

Соберём всё в одной схеме интернет-магазина:

```sql
-- Покупатели
CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    email TEXT NOT NULL UNIQUE,
    full_name TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Товары
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    sku TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    price NUMERIC(10, 2) NOT NULL CHECK (price > 0),
    category TEXT
);

-- Заказы (связь с покупателем)
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    customer_id INT NOT NULL REFERENCES customers (customer_id) ON DELETE RESTRICT,
    order_date DATE NOT NULL DEFAULT CURRENT_DATE,
    total NUMERIC(12, 2) CHECK (total >= 0)
);

-- Позиции заказа (связь заказов и товаров, много-ко-многим)
CREATE TABLE order_items (
    order_id INT REFERENCES orders (order_id) ON DELETE CASCADE,
    product_id INT REFERENCES products (product_id) ON DELETE RESTRICT,
    quantity INT NOT NULL CHECK (quantity > 0),
    unit_price NUMERIC(10, 2) NOT NULL CHECK (unit_price > 0),
    PRIMARY KEY (order_id, product_id)  -- составной первичный ключ
);
```

**Что здесь защищено:**
- Нельзя создать заказ для несуществующего покупателя (`FOREIGN KEY`).
- Нельзя удалить покупателя, у которого есть заказы (`ON DELETE RESTRICT`).
- Нельзя добавить в заказ несуществующий товар (`FOREIGN KEY`).
- Нельзя заказать отрицательное или нулевое количество (`CHECK`).
- Один и тот же товар не может дважды появиться в одном заказе (`PRIMARY KEY (order_id, product_id)`).
- При удалении заказа все его позиции удаляются автоматически (`ON DELETE CASCADE`).

### 2.8. Сводная таблица ограничений

| Ограничение | Что гарантирует | Уровень |
|---|---|---|
| `NOT NULL` | Значение всегда присутствует | Столбец |
| `UNIQUE` | Значения не повторяются | Столбец или таблица |
| `PRIMARY KEY` | Уникальный идентификатор строки | Столбец или таблица |
| `FOREIGN KEY` | Ссылка на существующую строку в другой таблице | Столбец или таблица |
| `CHECK` | Произвольное логическое условие | Столбец или таблица |
| `DEFAULT` | Значение при отсутствии явного | Столбец |

Ограничения — это первый и самый надёжный рубеж защиты данных. Даже если в приложении есть ошибка, база данных не позволит записать бессмысленные или противоречивые данные.

## Шаг 3: INSERT — Добавление данных

Команда `INSERT` используется для добавления новых строк в таблицу.

### Пример 1: Вставка одной строки с указанием всех столбцов

Вставляем первый товар. Поскольку `product_id` — это `SERIAL`, мы можем его не указывать, и база данных сгенерирует его автоматически (начиная с 1).

```sql
-- Вставляем одну строку в таблицу products
INSERT INTO products (name, price, category)
VALUES ('Ноутбук', 75000.00, 'Электроника');
```

**Подробный разбор:**
- `INSERT INTO products`: указываем, в какую таблицу добавляем данные.
- `(name, price, category)`: перечисляем столбцы, для которых будем передавать значения. `product_id` пропущен, так как он заполнится автоматически.
- `VALUES (...)`: ключевое слово, за которым следуют сами значения в том же порядке, что и столбцы.
- `'Ноутбук'`: строковые значения заключаются в одинарные кавычки.
- `75000.00`: числовое значение без кавычек.

**Результат:** PostgreSQL ответит `INSERT 0 1`, что означает успешную вставку одной строки.

### Пример 2: Вставка нескольких строк одновременно

PostgreSQL позволяет вставлять несколько строк одним запросом, что гораздо эффективнее, чем делать отдельный `INSERT` для каждой строки.

```sql
-- Вставляем сразу три строки в таблицу products
INSERT INTO products (name, price, category)
VALUES 
    ('Смартфон', 45000.00, 'Электроника'),
    ('Книга "SQL для начинающих"', 1200.50, 'Книги'),
    ('Настольная лампа', 3500.00, 'Освещение');
```

**Комментарии:**
- После `VALUES` мы перечисляем наборы значений в скобках, разделённые запятыми.
- Каждый набор в скобках соответствует одной новой строке.

**Результат:** PostgreSQL ответит `INSERT 0 3`, подтверждая вставку трёх строк.

### Пример 3: Вставка с предложением RETURNING

PostgreSQL имеет полезное расширение: вы можете сразу получить данные, которые были вставлены (например, сгенерированный `product_id`), используя `RETURNING`.

```sql
-- Вставляем товар и сразу возвращаем его ID и имя
INSERT INTO products (name, price, category)
VALUES ('Кофеварка', 8900.00, 'Бытовая техника')
RETURNING product_id, name;
```

**Результат:** База данных вернёт таблицу с только что созданными значениями (например, `product_id = 5`, `name = 'Кофеварка'`).

## Шаг 4: UPDATE — Изменение данных

Команда `UPDATE` изменяет существующие строки. **Критически важно** использовать условие `WHERE`, иначе вы обновите все строки в таблице.

### Пример 1: Обновление одного столбца в конкретной строке

Предположим, мы хотим повысить цену на ноутбук. Сначала нужно знать, как его идентифицировать. Мы знаем, что его имя — 'Ноутбук' (или можно использовать `product_id`, если он известен, например, 1).

```sql
-- Обновляем цену товара, где имя равно 'Ноутбук'
UPDATE products 
SET price = 82000.00 
WHERE name = 'Ноутбук';
```

**Подробный разбор:**
- `UPDATE products`: указываем таблицу для обновления.
- `SET price = 82000.00`: присваиваем столбцу `price` новое значение.
- `WHERE name = 'Ноутбук'`: **условие фильтрации**. Обновление затронет только те строки, для которых условие истинно. Если условие не совпадёт ни с одной строкой, ошибки не будет, просто будет обновлено 0 строк.

**Результат:** PostgreSQL ответит `UPDATE 1`, показывая, что изменена одна строка.

### Пример 2: Обновление на основе текущего значения (вычисляемое выражение)

Можно обновлять значения, используя их текущее состояние. Например, повысим цену всех товаров в категории 'Электроника' на 10%.

```sql
-- Увеличиваем цену на 10% для всех товаров в категории 'Электроника'
UPDATE products 
SET price = price * 1.10 
WHERE category = 'Электроника';
```

**Комментарии:**
- В правой части `SET` можно использовать выражения. Здесь `price * 1.10` берёт текущее значение `price` для каждой строки, умножает его на 1.10 и записывает обратно.
- Условие `WHERE category = 'Электроника'` гарантирует, что изменение затронет только нужную группу товаров.

### Пример 3: Обновление нескольких столбцов одновременно

Можно изменить несколько столбцов в одном запросе, перечислив их через запятую в `SET`.

```sql
-- Обновляем и цену, и категорию для конкретного товара по его ID
UPDATE products 
SET price = 1500.00, category = 'Учебная литература' 
WHERE product_id = 3;
```

**Комментарии:**
- Мы предполагаем, что `product_id = 3` соответствует книге. Запрос изменит и цену, и категорию для этой одной строки.

**Результат:** PostgreSQL ответит `UPDATE 1`.

## Шаг 5: DELETE — Удаление данных

Команда `DELETE` удаляет строки из таблицы. Как и в случае с `UPDATE`, **всегда используйте `WHERE`**, если не хотите удалить всё содержимое таблицы.

### Пример 1: Удаление конкретной строки по ID

Удалим товар, который мы создали с `product_id = 5` (Кофеварка).

```sql
-- Удаляем строку, где product_id равен 5
DELETE FROM products 
WHERE product_id = 5;
```

**Подробный разбор:**
- `DELETE FROM products`: указываем таблицу, из которой удаляем данные.
- `WHERE product_id = 5`: условие, определяющее, какие именно строки должны быть удалены.

**Результат:** PostgreSQL ответит `DELETE 1`, подтверждая удаление одной строки.

### Пример 2: Удаление по условию (диапазону)

Удалим все товары, цена которых ниже определённого порога, например, 2000.

```sql
-- Удаляем все товары с ценой меньше 2000
DELETE FROM products 
WHERE price < 2000.00;
```

**Комментарии:**
- Условие `price < 2000.00` выберет все строки, где цена меньше 2000. Это могут быть 0, 1 или несколько строк.

### Пример 3: Удаление с предложением RETURNING

Как и `INSERT`, `DELETE` может возвращать данные удалённых строк. Это полезно для подтверждения того, что было удалено.

```sql
-- Удаляем товары категории 'Освещение' и возвращаем их имена и цены
DELETE FROM products 
WHERE category = 'Освещение' 
RETURNING name, price;
```

**Результат:** База данных вернёт таблицу с именами и ценами всех удалённых строк (в данном случае — 'Настольная лампа', 3500.00).

### ⚠️ Важное предупреждение

Если выполнить `DELETE FROM products;` **без** `WHERE`, то будут удалены **все** строки из таблицы `products`. Таблица останется, но станет пустой. Это очень опасная операция в production-среде.

## Итог

Вы изучили базовый, но критически важный набор команд и концепций для работы с данными в PostgreSQL:

1. **Ограничения (constraints)** — `NOT NULL`, `UNIQUE`, `PRIMARY KEY`, `FOREIGN KEY`, `CHECK`, `DEFAULT` — обеспечивают целостность данных на уровне базы. Они срабатывают автоматически при каждой операции и не дают записать некорректные данные, даже если приложение содержит ошибку.
2. **`INSERT`**: добавляет новые строки. Можно использовать `RETURNING` для получения сгенерированных значений.
3. **`UPDATE`**: изменяет существующие строки. **Всегда используйте `WHERE`**, чтобы ограничить область изменений.
4. **`DELETE`**: удаляет строки. **Всегда используйте `WHERE`**, если не хотите очистить таблицу.

Эти команды составляют основу для любого взаимодействия с базой данных. Для дальнейшего изучения следующим шагом будет команда `SELECT` для извлечения и анализа данных.

## Шаг 6: Задачи на отработку знаний

Ниже — 7 практических задач. Выполняйте их по порядку: каждая следующая опирается на результаты предыдущих. Для проверки используйте `SELECT * FROM <таблица>;`.

### Задача 1: Создание таблицы с ограничениями

Создайте таблицу `employees` (сотрудники) со следующими требованиями:

- `employee_id` — автоинкрементный первичный ключ;
- `full_name` — обязательное текстовое поле;
- `email` — обязательное поле, значения должны быть уникальны;
- `salary` — числовое поле с двумя знаками после запятой, значение должно быть строго больше нуля;
- `department` — текстовое поле, по умолчанию должно принимать значение `'general'`;
- `hire_date` — дата, по умолчанию текущая дата (`CURRENT_DATE`);
- `manager_id` — целое число, ссылающееся на `employee_id` этой же таблицы (руководитель сотрудника).

**Подсказка:** используйте `SERIAL PRIMARY KEY`, `NOT NULL`, `UNIQUE`, `CHECK`, `DEFAULT` и `REFERENCES` на саму себя.

---

### Задача 2: Создание связанных таблиц

Создайте две таблицы:

**`authors` (авторы):**
- `author_id` — автоинкрементный первичный ключ;
- `name` — обязательное текстовое поле;
- `country` — текстовое поле.

**`books` (книги):**
- `book_id` — автоинкрементный первичный ключ;
- `title` — обязательное текстовое поле;
- `author_id` — целое число, обязательное, ссылающееся на `authors(author_id)` с поведением `ON DELETE CASCADE`;
- `price` — числовое поле, значение должно быть больше или равно нулю;
- `published_year` — целое число, значение должно быть в диапазоне от 1900 до 2100.

**Подсказка:** для диапазона используйте `CHECK (published_year BETWEEN 1900 AND 2100)`.

### Задача 3: Вставка данных

Используя таблицы из задачи 2:

1. Добавьте трёх авторов одним запросом `INSERT`.
2. Добавьте пять книг одним запросом `INSERT`. Убедитесь, что `author_id` ссылается на существующих авторов.
3. Добавьте ещё одну книгу, используя `RETURNING`, чтобы сразу получить её `book_id` и `title`.

**Подсказка:** для нескольких строк перечислите наборы значений в `VALUES` через запятую.

### Задача 4: Проверка ограничений на практике

Попробуйте выполнить следующие запросы и объясните, **почему** каждый из них завершится ошибкой:

1. `INSERT INTO books (title, author_id, price, published_year) VALUES ('Без автора', NULL, 500, 2020);`
2. `INSERT INTO books (title, author_id, price, published_year) VALUES ('Дешёвая книга', 1, -100, 2020);`
3. `INSERT INTO books (title, author_id, price, published_year) VALUES ('Старая книга', 1, 300, 1850);`
4. `INSERT INTO authors (name, country) VALUES (NULL, 'Россия');`

**Подсказка:** сопоставьте каждый запрос с конкретным ограничением (`NOT NULL`, `CHECK`, `FOREIGN KEY`).

### Задача 5: Обновление данных

Используя таблицу `books` из задачи 2:

1. Повысьте цену всех книг на 15% (используйте вычисляемое выражение в `SET`).
2. Измените `country` автора с `author_id = 2` на `'Германия'`.
3. Для всех книг, изданных до 2000 года, установите цену `999.99` и верните их `title` и `price` через `RETURNING`.

**Подсказка:** в третьем пункте можно совместить `UPDATE ... SET ... WHERE ... RETURNING ...`.

### Задача 6: Удаление данных

Используя таблицы `authors` и `books` из задачи 2:

1. Удалите книгу с `book_id = 5` и верните её `title` через `RETURNING`.
2. Удалите все книги, цена которых больше `5000`.
3. Удалите автора с `author_id = 3`. Объясните, что произойдёт с его книгами и почему.

**Подсказка:** в третьем пункте вспомните про `ON DELETE CASCADE`.

### Задача 7: Комплексная задача

Спроектируйте схему для простого блога и заполните её данными.

**Таблицы:**

- `blog_users`:
  - `user_id` — автоинкрементный первичный ключ;
  - `username` — обязательное, уникальное;
  - `email` — обязательное, уникальное;
  - `registered_at` — дата и время, по умолчанию `NOW()`.

- `posts`:
  - `post_id` — автоинкрементный первичный ключ;
  - `user_id` — обязательное, ссылается на `blog_users(user_id)` с `ON DELETE CASCADE`;
  - `title` — обязательное;
  - `body` — обязательное;
  - `published` — логическое поле (`BOOLEAN`), по умолчанию `FALSE`;
  - `views` — целое число, по умолчанию `0`, не может быть отрицательным.

**Что нужно сделать:**

1. Создайте обе таблицы.
2. Добавьте двух пользователей одним `INSERT`.
3. Добавьте три поста: два от первого пользователя, один от второго. Один из постов сразу опубликуйте (`published = TRUE`).
4. Обновите: всем постам пользователя с `user_id = 1` увеличьте `views` на 100.
5. Удалите пользователя с `user_id = 2` и объясните, сколько строк и в какой таблице будет удалено.
6. Попробуйте вставить пост с `views = -5` и объясните, какое ограничение сработает.

**Подсказка:** для шага 5 проверьте результат через `SELECT * FROM posts;` — постов второго пользователя быть не должно.
